# 🎓 Цифровой деканат будущего

> **Концепт для конкурса.** Это учебный прототип, а не официальный сервис какого-либо вуза.
> Все ФИО, оценки, номера зачёток и другие данные в проекте **вымышлены**.

Рабочий прототип личного кабинета студента **вымышленного университета «Хогвартс»**, в котором вся учебная жизнь собрана в одном месте: расписание, оценки, справки, заявления и связь с деканатом. Удобно с телефона, понятно без инструкций, безопасно по умолчанию.

Код проекта пишется с помощью ИИ-ассистентов (вайб-кодинг), а весь процесс работы с нейросетями документируется.

## ❓ Проблема

Сегодня учебная жизнь студента разбросана по разным местам:

| Что нужно студенту | Где это обычно находится |
|---|---|
| Расписание | на сайте вуза |
| Оценки | в отдельной системе |
| Справки | в очереди в деканате |
| Объявления | в чатах и на почте |

Найти нужное трудно, особенно с телефона. Студент тратит время на поиск информации и походы в деканат вместо учёбы.

## 💡 Идея решения

Единый личный кабинет — «цифровой деканат», который:

- **собирает всё в одном месте** — учёба, документы, связь с деканатом;
- **удобен и понятен** — нужное находится за пару касаний, без инструкций;
- **красив** — современный и приятный дизайн;
- **работает с телефона** — полноценно, а не только на компьютере;
- **безопасен** — каждый студент видит только свои данные.

Кабинет можно адаптировать под структуру, порядки и привычки конкретного вуза.

## ✨ Функциональность

### Обязательное ядро

| Раздел | Что внутри |
|---|---|
| 🔐 **Вход и профиль** | Вход по логину и паролю. Профиль студента: ФИО, факультет, направление, курс, группа |
| 📅 **Расписание** | Занятия на сегодня и на неделю, аудитория и преподаватель, заметные изменения и переносы |
| 📊 **Успеваемость** | Оценки и зачёты по дисциплинам, сессия, понятная картина «как у меня дела с учёбой»; деканат видит успеваемость своего факультета по курсам, группам и студентам |
| 📄 **Заявки и справки** | Заказ справки или подача заявления онлайн, отслеживание статуса заявки |
| 🔔 **Уведомления** | Новости и объявления деканата, напоминания о дедлайнах и изменениях |

### Главный сценарий для проверки

1. Студент входит в кабинет по логину и паролю.
2. Смотрит расписание на сегодня и видит перенос пары.
3. Открывает успеваемость и проверяет оценки за сессию.
4. Заказывает справку об обучении.
5. Видит статус заявки: *«Подана» → «В работе» → «Готова»*.
6. Получает уведомление о том, что справка готова.

> Как это сейчас в прототипе: о готовой справке и новой оценке кабинет сообщает на странице «Сегодня»
> и в разделах «Заявки» и «Оценки». Ленты уведомлений в интерфейсе пока нет — уведомления уже записываются
> в базу и ждут её.

## 📋 Требования к прототипу

- **Работающий прототип, а не макет.** Кабинет открывается по ссылке в браузере, по нему можно пройти все основные сценарии. Картинки и кликабельные макеты в Figma не считаются.
- **Адекватный и масштабируемый стек** — под разное количество пользователей.
- **Код пишут ИИ-ассистенты.**
- **Мобильная версия.** Все основные сценарии работают на экране шириной от **360 px**.
- **Только вымышленные данные.** Никаких настоящих ФИО, оценок, номеров зачёток. Без подключения к реальным системам вуза и без настоящих логинов и паролей. Парсинг открытых данных (например, расписания) разрешён.
- **Не выдаётся за официальный сервис.** На сайте явно указано, что это концепт для конкурса.
- **Без логотипа вуза.** Используется собственный логотип.
- **Доступность.** Прототип открывается из России без VPN и работает до объявления итогов — **28 ноября**.

## 🛡 Безопасность

Подробно — в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md#4-безопасность).

| Требование | Как реализовано |
|---|---|
| Студент видит только свои данные | Каждый запрос к базе фильтруется по владельцу из сессии на сервере. Чужая заявка по прямой ссылке → «Страница не найдена». Сотрудник видит только свой факультет |
| Пароли не хранятся в открытом виде | Только хеш argon2id с солью. В базе сессий — хеш токена, а не сам токен |
| Ключи и пароли не лежат в коде | Секреты — только в `.env` на сервере (файл в `.gitignore`), в репозитории — `.env.example` без значений |
| Защита от подбора пароля | Не больше 5 ошибок за 15 минут с одного адреса; посторонний не может заблокировать чужой аккаунт |
| Выданные пароли не утекают | Импорт пишет пароли студентов только в `credentials.csv` (в `.gitignore`), в консоль — никогда |
| Деканат видит только свой факультет | Успеваемость, группы, студенты и поиск фильтруются по факультету сотрудника из сессии; студент или группа другого факультета по прямой ссылке → HTTP 404; студент и преподаватель на `/staff/grades` перенаправляются в свой кабинет, API поиска отвечает им 403 |
| Преподаватель видит только свои группы | Журнал и сохранение оценок проверяют назначение преподавателя на сервере; чужая группа по прямой ссылке → 404. Частота сохранений ограничена — демо-аккаунт нельзя «завалить» |
| Проверено | Автотесты (`npm test`): безопасность, оценки (доступ преподавателя, долг, сводка), успеваемость деканата (чужой факультет, роли, агрегаты курса, поиск), импорт, расписание; сквозная проверка в браузере, аудит ИИ-субагентом `security-reviewer` |

### Как считаются оценки

Шкала — болонская (ECTS), одна константа в [`lib/grades/scale.ts`](lib/grades/scale.ts). Преподаватель ставит
**баллы 0–100** за три среза семестра и экзамен (зачёт — «зачтено / не зачтено»), буква выводится сама:

| Буква | Баллы | Расшифровка | 5-балльная |
|---|---|---|---|
| A | 90–100 | отлично | 5 |
| B | 82–89 | очень хорошо | 4 |
| C | 75–81 | хорошо | 4 |
| D | 67–74 | удовлетворительно | 3 |
| E | 60–66 | достаточно | 3 |
| FX | 35–59 | неудовлетворительно, можно пересдать | 2 |
| F | 0–34 | неудовлетворительно, нужно повторить курс | 2 |

Средний по дисциплине — среднее выставленных срезов; итоговый балл — среднее из средних дисциплин (без весов).
Экзамен и зачёт в средние не входят. Оценки ставит преподаватель семинаров группы (по расписанию), лектор потока — нет.
FX или F за срез — долг по дисциплине (FX — можно пересдать, F — нужно повторить курс); сданный экзамен (от 60 баллов)
или «зачтено» его гасит.

### Как устроены данные

Вся структура вуза — в трёх **заменяемых файлах** [`data/university/`](data/university/):

| Файл | Что внутри |
|---|---|
| `students.csv` | 990 студентов: ФИО, почта (из неё логин), зачётка, факультет, курс, академическая и две языковые группы |
| `schedule.csv` | расписание семестра и сессии в формате РУЗ: ~23,5 тыс. строк «занятие × группа», переносы и отмены |
| `campus-map.json` | корпуса и аудитории для карты кампуса |

Данные «Хогвартса» вымышлены и собраны генератором [`tools/schedule-generator/`](tools/schedule-generator/).
Чтобы показать кабинет на другом вузе, замените файлы своими с той же структурой и выполните
`npm run data:import` и `npm run db:seed`: импорт сначала проверит файлы и понятно перечислит ошибки
(«students.csv, строка 15: колонка «Академическая группа» — группы «1-ГР-9» нет в schedule.csv»),
а в базу загрузит всё одной транзакцией. Формат файлов — [`data/university/README.md`](data/university/README.md).

## 🚀 Запуск проекта

### Посмотреть без установки — GitHub Codespaces

[![Open in GitHub Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/arseniichugin/student_account?quickstart=1)

Кабинет запускается на виртуальной машине GitHub прямо в браузере — ничего не нужно скачивать.
Нажмите кнопку выше (или **Code → Codespaces → Create codespace on main**), подождите 3–5 минут — кабинет
откроется в новой вкладке. Подробности — [`.devcontainer/README.md`](.devcontainer/README.md).
Не забудьте остановить Codespace после работы: он расходует бесплатную месячную квоту GitHub.

### На своём компьютере

Нужны **Git**, **Node.js 22+** и **Docker Desktop** (для базы данных).

**1. Скачать проект и установить зависимости**

```bash
git clone https://github.com/arseniichugin/student_account.git
cd student_account
npm install
```

**2. Создать файл настроек** (секреты хранятся только в нём, в репозиторий он не попадает)

```bash
cp .env.example .env
```

**3. Запустить базу данных** (Docker Desktop должен быть открыт)

```bash
docker compose up -d db
```

**4. Создать таблицы, загрузить данные вуза и демо-наполнение**

```bash
npm run db:setup
```

**5. Запустить кабинет**

```bash
npm run dev
```

Откройте http://localhost:3000 и войдите под любым [тестовым аккаунтом](#-тестовые-аккаунты).

### Полезные команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Запуск в режиме разработки |
| `npm test` | Автотесты: безопасность, оценки, импорт, расписание, карта (нужна база после `npm run db:setup`) |
| `npm run lint` / `npm run typecheck` | Проверка кода |
| `npm run data:import` | Проверить и загрузить файлы вуза из `data/university` (`-- --check` — только проверить) |
| `npm run db:seed` | Пересоздать демо-контент: заявки, оценки, объявления, уведомления |
| `npm run db:migrate` | Применить изменения схемы базы (при разработке) |
| `npm run db:reset` | Пересоздать базу с нуля: миграции + импорт данных вуза + демо-контент (все данные удаляются) |

### Запуск целиком в Docker (как на сервере)

```bash
mkdir -m 700 secrets            # сюда импорт запишет credentials.csv
docker compose run --rm migrate
docker compose up -d app
```

В Docker логины и пароли студентов появляются в `secrets/credentials.csv` (папка в `.gitignore` и `.dockerignore`),
а не в корне проекта: контейнеру импорта открыта на запись только эта папка.

## 🏆 Критерии оценки

Каждый критерий — до 10 баллов, итог — среднее по оценкам всех экспертов.

| Критерий | На что смотрят |
|---|---|
| **Проработанность идеи** | Понятна проблема студентов, сценарии построены вокруг реальных задач, ядро реализовано полностью, есть смелые идеи |
| **Масштаб использования нейротехнологий** | Продуманность процесса, качество промптов, документы для ИИ-агентов, работа с ошибками ИИ, ИИ для дизайна и контента |
| **Имплементация** | Прототип открывается и работает без ошибок, данные сохраняются, работает на телефоне, соблюдена безопасность, тестовые аккаунты работают |
| **Качество** | Цельный современный дизайн, понятная навигация, продуманы пустые состояния, ошибки и загрузка, интерфейс быстрый и доступный |

# Спецификация: успеваемость и кабинет преподавателя

Документ для ИИ-агентов, которые делают этап 3 «Успеваемость». Решения согласованы с заказчиком
10 ноября 2026. Если что-то здесь противоречит `CLAUDE.md` — прав `CLAUDE.md`; если чего-то не хватает —
выбери самый простой вариант и запиши его в отчёт, а не выдумывай сложное.

## 1. Роли

| Роль | Кто | Что делает с оценками |
|---|---|---|
| `STUDENT` | студент | видит **только свои** оценки текущего семестра; прошлые семестры — пустое состояние |
| `TEACHER` (новая) | преподаватель из `schedule.csv` | видит полный список студентов **своих** групп и ставит им оценки |
| `STAFF` | деканат | **пока не трогаем**: дизайн просмотра оценок деканатом согласуем с заказчиком отдельно |

**Кто «свой» преподаватель группы.** Оценки ставит **преподаватель семинаров** у этой группы: тот, кто ведёт
у неё занятия вида «Семинар» или «Практическое занятие» по этой дисциплине (занятия со статусом `REPLACED`
не считаются — это разовая замена). Лектор потока оценки **не ставит**. Если семинаристов у пары
«дисциплина × группа» двое (в данных 3 таких пары) — ставить могут оба.
Группа — та, что указана в занятии: для языков это языковая подгруппа (`1-ГР-1 (5)`, 5–9 человек), для
остальных дисциплин — академическая группа (`1-ГР-1`).

Студенты группы: академическая — `Student.academicGroupId`; языковая — `StudentGroup`.

## 2. Учебный период

- Текущий семестр студента — осенний семестр 2026/27: номер `2 × (курс − 1) + 1`.
  Учебный год и сезон задаются в одном месте (`lib/grades/term.ts` или аналог), а не размазаны по коду.
- Дисциплины семестра студента — все дисциплины, по которым у его академической группы или его языковых
  групп есть занятия в расписании (8–9 дисциплин).
- **Три среза** в семестре: «1-й срез», «2-й срез», «3-й срез». Ориентировочные сроки для подписи в интерфейсе:
  до 10 октября, до 15 ноября, до 15 декабря (задать в том же модуле периода).
- **Итоговый контроль** дисциплины для группы берётся из расписания: есть занятие вида «Экзамен» → экзамен,
  есть «Зачёт» → зачёт (в данных у каждой пары «дисциплина × группа» ровно одно из двух). Дата — дата этого занятия.

## 3. Шкала оценок — болонская (ECTS), баллы + буквы

Срезы и экзамен оцениваются в **баллах 0–100**; буква ECTS и традиционная оценка выводятся из баллов
автоматически. Преподаватель вводит баллы (и сразу видит букву), студент везде видит **букву крупно**
и баллы рядом. Зачёт — отдельно: «зачтено» / «не зачтено».

| Буква | Баллы | Расшифровка | 5-балльный эквивалент |
|---|---|---|---|
| A | 90–100 | отлично | 5 |
| B | 82–89 | очень хорошо | 4 |
| C | 74–81 | хорошо | 4 |
| D | 64–73 | удовлетворительно | 3 |
| E | 60–63 | достаточно | 3 |
| FX | 35–59 | неудовлетворительно, можно пересдать | 2 |
| F | 0–34 | неудовлетворительно, нужно повторить курс | 2 |

Шкала — **одна** константа в одном модуле (`lib/grades/scale.ts`): границы, подписи, цвета-токены. Её же
показываем студенту в подсказке «Как считаются оценки». Вузы используют разные границы; эта — самая
распространённая ECTS-таблица со 100-балльной шкалой, заменить её можно в одном месте.

**Средние:**
- Средний балл по дисциплине = среднее арифметическое **выставленных** срезов (пустые не считаются),
  округление до 1 знака; буква — по шкале. Нет ни одного среза — «нет оценок», а не 0.
- **Итоговый балл по всем дисциплинам** = среднее из средних баллов дисциплин, у которых есть хотя бы
  один срез («среднее из средних», без весов). Буква — по шкале.
- Итоговая оценка за экзамен/зачёт в средние **не входит**: показывается отдельно.

## 4. Модель данных

Модель `Grade` перестраивается (сейчас в интерфейсе её никто не читает; демо-данные пересоздаёт seed).
Минимум полей:

- `studentId`, `disciplineId`, `semester` (номер семестра студента), `kind`:
  `CHECKPOINT` (срез) · `EXAM` · `CREDIT`;
- `checkpoint` — 1, 2 или 3 для среза, пусто для экзамена/зачёта;
- `points` (0–100) — для среза и экзамена; `passed` (boolean) — для зачёта;
- `gradedByTeacherId` (кто поставил, `onDelete: SetNull`), `createdAt`, `updatedAt`;
- уникальность: одна оценка на `(studentId, disciplineId, semester, kind, checkpoint)` — учти, что в
  PostgreSQL `NULL` в уникальном индексе не равен `NULL`, поэтому для экзамена/зачёта храни `checkpoint = 0`
  или сделай отдельный уникальный индекс — главное, чтобы дубль был невозможен.

Таблица назначений (имя на твой вкус, например `TeachingAssignment`): `teacherId`, `disciplineId`,
`groupId`, `finalKind` (`EXAM` / `CREDIT`), `finalDate?`. Её **заполняет импорт** из расписания
(правило из §1). Она — единственный источник правды для доступа преподавателя.

Учётная запись преподавателя: `Teacher.userId` (необязательная связь 1:1 с `User`, роль `TEACHER`).

## 5. Импорт (`npm run data:import`)

- Для каждого преподавателя с почтой — учётная запись. **Логин = часть почты до `@`** (`p.arseneva`).
  Пароль — случайный (`generatePassword`), хеш argon2id, строка в `credentials.csv` с ролью «преподаватель».
- Повторный импорт сохраняет аккаунт, пароль и оценки (преподаватель узнаётся по `Teacher.oid`).
- Проверка: логин преподавателя не совпадает с логином студента или `dekanat.*` — иначе понятная ошибка
  валидации, база не меняется.
- **Два тестовых преподавателя для жюри** (`isDemo`, пароль `DEMO_PASSWORD`, по умолчанию `Hogwarts2026`):
  выбираются автоматически — семинаристы, у которых учится тестовый студент 1 (`larisa.sharova26`) и
  тестовый студент 2 (`eva.orlova25`); разные люди. Переменная `TEST_TEACHER_LOGINS` (по аналогии с
  `TEST_STUDENT_LOGINS`) позволяет задать их явно. Импорт печатает их в списке тестовых аккаунтов.
- Импорт заполняет таблицу назначений.

## 6. Демо-наполнение (`npm run db:seed`)

- Оценок за прошлые семестры **нет** (их генерацию убрать).
- Текущий семестр (сегодня — 10 ноября): **1-й срез выставлен всем**, **2-й срез — примерно половине пар
  «дисциплина × группа»** (детерминированно), 3-й срез и итоговые оценки — пусто. Баллы правдоподобные
  (в основном 60–100, изредка FX). Оценки ставит «свой» преподаватель (заполнить `gradedByTeacherId`).
- Тестовый студент 2 (`eva.orlova25`) — «долг»: FX за 1-й срез по одной дисциплине. Там, где seed раньше
  ссылался на долг прошлого семестра (комментарий к отклонённой выписке), — поправить текст под новую ситуацию.
- У тестового преподавателя 1 должна остаться хотя бы одна группа с невыставленным 2-м срезом, чтобы жюри
  могло само поставить оценку и увидеть её у студента.

## 7. Безопасность (жёстко)

- `requireTeacher()` → `TeacherContext` (брендированный тип, как `StudentContext`), только из сессии.
- Все запросы — в `lib/data/grades.ts` (или рядом), функции принимают контекст, а не голый id.
- Студент читает только оценки `studentId` из сессии.
- Преподаватель читает список студентов и оценки **только** по своим назначениям; сохранение проверяет
  **на сервере**: назначение (`teacherId` из сессии + дисциплина + группа) существует, студент состоит
  в этой группе, вид оценки соответствует итоговому контролю (нельзя поставить «экзамен» за зачётную
  дисциплину), значение проходит Zod (баллы — целое 0–100; срез 1–3). Иначе — отказ без утечки данных
  (как `notFound()` для чужого).
- Демо-режим не запрещает ставить оценки (это главный сценарий для жюри).
- При сохранении оценки студенту создаётся уведомление (`Notification`, новый тип `GRADE`):
  «Новая оценка: <дисциплина>, 2-й срез — B (85)», ссылка на `/grades`.
- Автотесты: чужая группа; студент не из группы; экзамен вместо зачёта; баллы 101 / −1 / дробные;
  студент не видит чужие оценки; преподаватель без назначения не видит группу.

## 8. Интерфейс

Две полноценные раскладки — **телефон (от 360 px) и компьютер (≥ 1024 px)**; на телефоне нижняя панель,
на компьютере боковое меню (уже есть в `AppShell`). Токены и компоненты — из `docs/DESIGN.md`.
Каждый экран: загрузка (скелетон), пусто, ошибка с «Повторить».

**Студент — `/grades`, пункт меню «Оценки»** (6-й пункт; проверить, что на 360 px все 6 помещаются,
область нажатия ≥ 44 px):
- переключатель семестров: текущий + прошлые (`1 … текущий−1`); прошлые — пустое состояние
  «Оценок за этот семестр в кабинете нет»; у первокурсника прошлых нет;
- сводка: итоговый балл по всем дисциплинам (буква + баллы), сколько срезов выставлено из возможных,
  ближайший экзамен/зачёт;
- **график статистики** — собственный SVG без новых библиотек: например, столбики среднего балла по
  дисциплинам с цветом буквы и линия/точки по срезам; подписи и `aria`-описание, читается в тёмной теме;
- карточка дисциплины: 1-й/2-й/3-й срез (буква + баллы, «—» если нет), средний, итоговый контроль
  (экзамен/зачёт, дата), итоговая оценка, преподаватель семинаров;
- подсказка «Как считаются оценки» со шкалой из `lib/grades/scale.ts`.

**Преподаватель — роль `TEACHER`**, меню: «Журнал» (`/journal`, главная), «Расписание» (по умолчанию —
своё расписание), «Карта», «Профиль» (ФИО, должность, почта, смена пароля — с тем же запретом для
демо-аккаунтов).
- `/journal` — карточки «дисциплина × группа»: название, группа, число студентов, вид контроля,
  прогресс по срезам («2-й срез: 12 из 20»);
- `/journal/[assignmentId]` — журнал группы: все студенты (ФИО, зачётка), срезы 1–3, средний, итоговая.
  Компьютер — таблица с полями ввода баллов и мгновенной буквой; телефон — карточки студентов.
  Сохранение строкой или всей колонкой; ошибка — у поля; успех — заметное подтверждение.
  Итоговая: экзамен — баллы 0–100 (+ буква), зачёт — «зачтено / не зачтено».
  Чужой `assignmentId` → 404.

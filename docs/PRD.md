# PRD — требования к продукту

> Статус: **черновик**. Обновляется по итогам опроса однокурсников (`research/survey.md`).
>
> **Вуз:** вымышленный **«Хогвартс»**: 4 факультета (Гриффиндор, Слизерин, Когтевран, Пуффендуй),
> 990 студентов, расписание семестра и сессии. Данные — в заменяемых файлах `data/university/`:
> кабинет можно показать на другом вузе, заменив три файла.

## 1. Проблема

Учебная жизнь студента разбросана по разным местам:

| Задача студента | Где решается сейчас | Что не так |
|---|---|---|
| Узнать расписание | сайт вуза | неудобно с телефона, переносы теряются |
| Посмотреть оценки | отдельная система | нет общей картины «как у меня дела» |
| Получить справку | очередь в деканате | время, часы работы, неизвестен статус |
| Узнать новости | чаты, почта | тонут среди сообщений, нет напоминаний |

_Сюда добавить цифры и цитаты из опроса._

## 2. Решение

Один кабинет, в котором всё нужное для учёбы — **за пару касаний с телефона**.
Главная идея: кабинет не просто показывает данные, а **отвечает на вопросы студента**:
«Куда мне сейчас идти?», «Всё ли у меня в порядке с учёбой?», «Готова ли моя справка?».

## 4. Ключевые сценарии

| # | Сценарий | Шаги | Критерий успеха |
|---|---|---|---|
| S1 | Утро перед парами | Вход → главная «Мой день» | За 1 экран видно: следующая пара, аудитория, время до начала, переносы |
| S2 | Перенос пары | Получено уведомление → открыть → расписание | Изменение выделено и показано как «было → стало» |
| S3 | Как у меня дела | Вкладка «Успеваемость» | Видны оценки, долги, средний балл и простой итог одной фразой |
| S4 | Заказать справку | «Заявки» → «Новая» → выбрать тип → отправить | Не больше 3 шагов, заявка сразу видна в истории со статусом |
| S5 | Справка готова | Сотрудник меняет статус → студент получает уведомление | Статус обновился, понятно, где и когда забрать / скачать |
| S6 | Защита данных | Студент подставляет id чужой заявки в адрес | Видит «Не найдено», данные не раскрываются |

## 5. Разделы и критерии готовности

### 5.1 Вход и профиль
- Вход по логину и паролю; понятные ошибки («Неверный логин или пароль» — без уточнения, что именно).
- Ограничение попыток входа.
- Профиль: ФИО, факультет, направление, курс, группа, номер студенческого (вымышленный).
- Смена пароля, выход.

### 5.2 Главная «Мой день»
- Следующая пара: название, время до начала, аудитория, преподаватель.
- Предупреждение о переносах на сегодня.
- Ближайшие дедлайны, активные заявки, непрочитанные объявления.

### 5.3 Расписание
- Режимы «Сегодня» и «Неделя», переключение недель.
- Тип занятия (лекция / семинар / лабораторная), аудитория, преподаватель.
- Переносы и отмены визуально заметны.

### 5.4 Успеваемость
- Оценки и зачёты по дисциплинам текущего и прошлых семестров.
- Сессия: экзамены, даты, результаты.
- Средний балл и итог: «Всё хорошо» / «Есть долги: N».

### 5.5 Заявки и справки
- Каталог: справка об обучении, справка для военкомата, справка о стипендии, заявление на академический отпуск и др.
- Форма с минимальным числом полей; данные студента подставляются автоматически.
- Статусы: **Подана → В работе → Готова → Выдана**, а также **Отклонена** с причиной.
- История заявок с датами.

### 5.6 Уведомления
- Лента объявлений деканата и персональных уведомлений.
- Типы: объявление, изменение расписания, статус заявки, дедлайн.
- Отметка «прочитано», счётчик непрочитанных.

### 5.7 Кабинет сотрудника
- Очередь заявок с фильтром по статусу; смена статуса и комментарий.
- Публикация объявлений для факультета / курса / группы.

## 6. Нефункциональные требования

- Работает на экранах от 360 px; основные сценарии — до 3 касаний.
- Каждый экран: состояния загрузки, пустоты и ошибки.
- Безопасность — см. `ARCHITECTURE.md`, раздел «Безопасность».
- Доступен из России без VPN до 28 ноября 2026.
- Бейдж «Концепт для конкурса» на всех страницах.

## 7. Вне рамок прототипа

- Интеграция с реальными системами вуза.
- Оплата обучения, общежития.
- Нативные мобильные приложения (вместо них — адаптивный сайт / PWA).

# Дневник работы с ИИ

Здесь фиксируется, как проект создавался с помощью нейросетей: какие задачи ставились,
какие промпты сработали, где ИИ ошибался и как это исправлялось.
Из этого файла и папки `screenshots/` собирается итоговый отчёт для жюри.

## Как вести

После каждой заметной задачи добавляй запись по шаблону (новые — сверху):

```markdown
### ГГГГ-ММ-ДД · Этап N · Короткое название
**Инструмент:** Claude Code / Cursor / Kandinsky / …
**Задача:** что нужно было сделать
**Промпт:** ключевой запрос (дословно или близко к тексту)
**Результат:** что получилось, какие файлы созданы
**Ошибки ИИ и исправления:** что пошло не так и как поправили (если было)
**Сделано вручную:** что человек сделал сам
**Скриншоты:** screenshots/…
```

## Записи

### 2026-11-08 · Этап 2 · Каркас, вход и безопасность
**Инструмент:** Claude Code (+ Playwright для проверки в браузере, Docker для проверки сборки)
**Задача:** проект Next.js, база данных, вход, разграничение доступа, вымышленные данные, заявки.
**Промпты:** «Перенеси в main и переходим к этапу 2. Дедлайн сдачи — 22 число, кабинет делаем
под вымышленный вуз» → (уточняющий вопрос пользователя о том, что установить на компьютер) → «Да, продолжи этап 2».
**Результат:**
- Next.js 16 + Prisma 7 + PostgreSQL, схема из 16 таблиц, миграция.
- Вход с argon2id, сессиями в базе (хранится хеш токена), ограничением 5 попыток / 15 минут.
- Слой данных с обязательным фильтром по владельцу; «контексты» студента и сотрудника.
- Страницы: вход, «Сегодня» (временная), заявки (список, подача, карточка), профиль со сменой пароля,
  кабинет сотрудника (заявки своего факультета, смена статуса → уведомление студенту).
- Seed: вымышленный Университет «Горизонт», 3 студента, 2 сотрудника, расписание на весь семестр.
- 11 автотестов безопасности, Dockerfile + docker-compose.yml.

**Ошибки ИИ и как их нашли и исправили:**

| # | Что пошло не так | Как обнаружено | Исправление |
|---|---|---|---|
| 1 | ИИ «по памяти» собирался писать код под старый Next.js | Шаблон Next.js 16 содержит `AGENTS.md`: «This is NOT the Next.js you know» | ИИ прочитал документацию из `node_modules/next/dist/docs`, выяснил, что включён новый режим `cacheComponents`, и осознанно отключил его (решение записано в `ARCHITECTURE.md`) |
| 2 | Конфликт версий при установке Vitest (`@types/node@20` против требования `^22`) | Ошибка `npm install` | Обновлён `@types/node` до 22 |
| 3 | После неверного пароля форма стирала логин — неудобно | Сквозная проверка Playwright: второй вход не срабатывал | Логин возвращается из серверного действия и подставляется в поле |
| 4 | У сотрудника после сохранения список статусов показывал старое значение | **ИИ сам заметил на скриншоте**: бейдж «В работе», а в списке «Подана» | Первая попытка (управляемые поля) не помогла — снова проверено скриншотом. Вторая: отправка через `onSubmit`, без автосброса формы React 19 |
| 5 | `next build` в Docker падал: подключение к базе создавалось при загрузке модуля | Сборка Docker-образа (на компьютере не проявлялось из-за файла `.env`) | Ленивое создание клиента Prisma в `lib/db.ts` |
| 6 | Тестовый сценарий кликал не ту кнопку (`button[type=submit]` находил «Выйти» в шапке) и ждал не тот `role="alert"` (у Next.js есть свой) | Тест «падал», хотя кабинет работал | Уточнены селекторы — ошибка была в проверке, а не в кабинете |
| 7 | Браузер получал файлы от прошлой сборки | Ошибки 500 и MIME в консоли браузера | Старый сервер не остановился; добавлено правило в `CLAUDE.md` |

**Как проверено:** `npm run lint`, `npm run typecheck`, `npm test` (11/11), `npm run build`;
сквозной сценарий в браузере на 360 px (вход → заявка → подмена адреса → 404 → сотрудник меняет статус →
студент видит «В работе»); тот же сценарий против Docker-стека.
**Сделано вручную:** выбор дедлайна и вымышленного вуза, решение продолжать в облаке.
**Скриншоты:** `screenshots/2-2026-11-08-*.png`

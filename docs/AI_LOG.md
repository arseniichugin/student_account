# Дневник работы с ИИ

Здесь фиксируется, как проект создавался с помощью нейросетей: какие задачи ставились,
какие промпты сработали, где ИИ ошибался и как это исправлялось.
Из этого файла и папки `screenshots/` собирается итоговый отчёт для жюри.

```markdown

**Скриншоты:** screenshots/…
```

### 2026-11-10 · Этап 3 · Исправления интерфейса по независимому ревью
**Инструмент:** Claude Code — субагент «исправления интерфейса» в отдельном git worktree (параллельно с субагентом безопасности) + Playwright
**Задача:** исправить 14 замечаний `ui-reviewer`: переход «аудитория → карта» на телефоне, клавиатура и фокус на карте,
области нажатия, контраст в тёмной теме, поиск расписания при открытой клавиатуре, озвучивание подсказок,
ошибка карты без технических подробностей, заглушка на исходной дате переноса, заголовки и подписи.
**Промпт (сокращённо):** «Чини работоспособность, доступность и мобильную версию, без редизайна… повтори сценарии
ревьюера по каждому пункту и измерь».
**Результат:**
- Карта (`public/campus-map/`): карточка помещения — сразу под планом; по ссылке на телефоне — «Крупнее», план
  в окне с прокруткой, аудитория по центру, страница прокручена так, чтобы аудитория и карточка были между шапкой
  и нижним меню (замер 360×780: карточка 385–715 px, аудитория 189–281 px при видимой области 91–723; высота номера
  14 px). Фокус после перерисовки возвращается на кнопку, после выбора — на заголовок карточки, Esc закрывает
  карточку; видимая обводка фокуса 4 px; этажи — кнопки с `aria-pressed`; все кнопки ≥ 44 px; `aria-live` в поиске.
- Контраст в тёмной теме: выбранная аудитория и этаж 2.9:1 → 6.6:1 (`--hm-on-accent`), деканат 4.1 → 5.6:1,
  служебные 3.1 → 5.4:1.
- Поиск расписания: подсказки под полем (в окне 360×440 первая подсказка была за краем, стала 184–265 px),
  «Найдено: N. Стрелки вверх и вниз — выбор, Enter — открыть», Esc в два шага, клик вне закрывает,
  Enter без выбора — первая подсказка, без ссылок внутри `role=option`.
- Перенос: на исходной дате — «Перенесено на 06.11, 4-я пара» (`lib/data/schedule-moves.ts`, разбор причины —
  `lib/schedule/moves.ts`, тесты); «1 пара» → «1-я пара»; заголовки занятий h3/h4 по контексту.
**Ошибки ИИ и исправления:**
- Первая версия прокручивала к аудитории сразу после монтирования карты, пока над ней ещё стоял скелетон загрузки —
  после его удаления всё съехало бы вверх. Открытие аудитории перенесено в эффект после отрисовки без скелетона.
- Чипы факультетов в одну строку с прокруткой дали горизонтальную прокрутку всей страницы на 360 px:
  у `<fieldset>` по умолчанию `min-width: min-content`. Найдено замером Playwright, исправлено `min-w-0`.
- Подсказка «Tab — к списку» в поиске карты была неправдой (Tab уводит на выбор корпуса) — заменена
  на «стрелка вниз — к списку» и добавлена навигация стрелками.
**Скриншоты:** замеры и скриншоты до/после — в рабочей папке субагента (flow-*-map-360-after.png и др.)

### 2026-11-09 · Этап 3 · Расписание, карта, Хогвартс — оркестрация субагентов
**Инструмент:** Claude Code — оркестратор + субагенты-исполнители в отдельных git worktree
(«данные», «карта», «интерфейс расписания») + ревьюеры `security-reviewer`, `ui-reviewer`
**Промпт (сокращённо):** «Разбери структуру добавленных данных, разложи по папкам, при необходимости
пересобери репозиторий. Интегрируй расписание: поиск по группе и преподавателю и „Мой день“. Отдельная
вкладка карты; из расписания — переход на карту с подсветкой аудитории. CSV студентов и карта должны
легко заменяться файлами той же структуры. Горизонт → Хогвартс. Задай уточняющие вопросы, затем с
субагентами действуй автономно» + «Качество важнее лимитов: в конце итоговая проверка и исправления».

**Как шла работа:**
1. **Анализ и вопросы.** Оркестратор разобрал две ветки человека (~88 тыс. строк) и нашёл проблемы:
   данные в 4 копиях (CSV, JSON 21 МБ, SQLite 5 МБ, справочник), студенты только в JSON, скрипт карты
   искал базу не по тому пути (карта собиралась синтезом, а не из данных), `.dockerignore` не пускал данные
   в сборку, файлы названы именем реального вуза. Задано 8 вопросов + 2 уточнения (пометка «концепт»,
   пароли). Решения человека: CSV для студентов, вариант «аккаунт каждому», «Сегодня» = «мой день»,
   расписание видно всем вошедшим, пометки сохранить, в `main` — только проверенное.
2. **Фаза 0 (оркестратор).** Новая структура: `data/university/` — три заменяемых файла;
   `tools/schedule-generator/` и `tools/campus-map/` — генераторы. Генератор теперь пишет `students.csv`
   (русские заголовки, `;`, UTF-8 с BOM — открывается в Excel) и `schedule.csv` с колонкой `status`
   (в исходном CSV статуса переноса/отмены не было — он жил только в JSON, который удалялся).
   Проверено: расписание совпало строка в строку, все 136 аудиторий есть на карте, группы всех 990
   студентов есть в расписании, карта из базы идентична закоммиченной.
3. **Фаза 1 и 2 параллельно.** Субагенты «данные» и «карта» работали одновременно в своих worktree,
   со своими базой и портом. Оркестратор дал каждому зону ответственности и запрет трогать чужие файлы.
   - «Данные»: новая схема БД, импорт `npm run data:import` (проверка всех файлов до записи, ошибки
     по-русски с номером строки, всё-или-ничего, ~10 с), 990 аккаунтов + деканаты по факультетам,
     `credentials.csv` вне git, слой данных расписания, 45 тестов, проверка заменяемости на 3 наборах.
   - «Карта»: вкладка `/map?room=…`, проверка файла карты, защита от внедрения кода через данные,
     22 теста, 30 сценариев в браузере.
4. **Сведение.** Оркестратор слил ветки, разрешил конфликт, перевёл свою базу на новую схему:
   67 тестов зелёные на объединённом коде.

**Ошибки ИИ и исправления:**

| Что пошло не так | Кто/как обнаружил | Исправление |
|---|---|---|
| ТЗ «экранировать 8 мест с innerHTML» было неточным: все 8 — очистка элемента, данные шли через textContent | Субагент «карта» проверил код вместо буквального выполнения | `innerHTML` убран совсем, тест не даёт ему вернуться; буквальное экранирование показало бы `&lt;` вместо текста |
| В campus-map.js переменная использовалась до объявления | Не линтер и не сборка, а Playwright | Исправлено; ошибка монтирования карты больше не роняет страницу |
| Повторный импорт падал, если в новом наборе те же ID у других людей | Проверка заменяемости на наборе с другим seed | Двухфазная смена логинов + тест |
| Первая версия импорта перезаписывала `credentials.csv` — выданные пароли терялись бы | Субагент «данные» при самопроверке | Файл дополняется, пишется атомарно, права 600 |
| Рабочие копии субагентов попали под ESLint — тысячи ложных ошибок | Оркестратор при сведении | `.claude/**` исключён из ESLint и TypeScript, `.claude/worktrees/` — в `.gitignore` |
| Ни один субагент не заметил: в Docker-образ приложения не попадают файлы вуза — карта на сервере не открылась бы | Оркестратор при разборе Docker-конфигурации | Файлы копируются в образ и подключаются томом |
| Субагенты стартовали не от той ветки (рабочая копия создаётся от `main`) | Субагент «карта» сообщил в отчёте | В задании следующему субагенту — явный коммит, от которого начинать |

**Сделано вручную:** ответы на вопросы и решения по архитектуре данных, требования к заменяемости.


### 2026-11-08 · Карта кампуса
**Инструмент:** Claude Code (встроенный браузер для изучения референса, headless Edge для проверки, отдельный субагент-ревьюер)
**Задача:** интерактивная карта кампуса на основе правил нумерации аудиторий и карты МГИМО (https://mgimo.ru/territory/).
**Промпт:** «Создай мне интерактивную карту нашего хогвартса на основе данных о нумеровании аудиторий… Не копируй конфигурацию здания. Изучи карту, проанализируй закономерности в нумеровании аудиторий, соотнеси их с нашими правилами, сгенерируй новую карту.»
**Результат:** `public/campus-map/` — изометрическая схема кампуса, поэтажные планы со стенами, коридором, цветами типов помещений, лестницами, WC и переходами; поиск, фильтры, карточка с маршрутом, ссылка `#room=…`; деканаты и кафедры отмечены значками. Скрипт `scripts/build_map_data.py` собирает данные из базы расписания.
**Ошибки ИИ и исправления:** первая версия была «примитивной» (полосы кабинетов) — переделана по поэтажным планам МГИМО; предпросмотр не открывался из-за `</script>` в комментарии JS; переходы упирались в лестницы, технические помещения были узкими полосками, маршрут путал стороны в зеркальном крыле — найдено субагентом-ревьюером и исправлено.
**Сделано вручную:** 6 раундов замечаний к внешнему виду и логике карты.

### 2026-11-08 · Данные · Синтетическое расписание «Хогвартса»
**Инструмент:** Claude Code (приложение Claude для ПК) + встроенный браузер (mgimo.ru, поиск формата групп)
**Задача:** сгенерировать правдоподобное расписание на семестр и сессию для 4 факультетов × 4 курсов × 3 групп
по готовой спецификации `schedule/spec/mgimo_schedule_schema.md` (модель РУЗ МГИМО)
**Промпт:** «Ты мой помощник в генерации расписания… сделай генерацию по 4 факультетам Хогвартса… не более
10 предметов плюс иностранные языки… В процессе генерации обращайся ко мне и задавай уточняющие вопросы»
**Как шла работа:**
1. ИИ прочитал спецификацию и ТЗ и задал вопросы в несколько заходов: какие предметы и как распределить по курсам,
   как называть преподавателей, как собирать потоки, как раздавать языки, какие сетки пар, как нумеровать
   аудитории, какие форматы выдать, нужны ли зачёты и экзамены.
2. Формат названий групп ИИ пытался взять с ruz.mgimo.ru. Сайт не открылся ни в браузере, ни через API
   (нет соединения), поэтому формат задал человек: `1-ГР-1`, языковая группа `1-ГР-1 (5)`.
3. ИИ написал генератор `schedule/generator/generate_hogwarts_schedule.py` и встроил в него проверки
   из раздела 10 спецификации и ещё 17 своих. Итог: 990 студентов, 333 группы, 106 преподавателей,
   около 21 тыс. занятий, 0 нарушений жёстких правил.
4. По просьбе человека добавлено личное расписание каждого студента: представления `student_schedule`
   и `student_lessons` в SQLite и поле `scheduleGroupOids` в `students.json`. Почта и ссылки на онлайн-занятия
   переведены на вымышленный домен `hogwarts.example.org`.

**Ошибки ИИ и исправления:**

| Расписание не собиралось: практикумам в обсерватории не хватало залов | Генератор падал на всех seed; диагностика по типам аудиторий | 1 и 4 курс разведены по чётности недель, для обсерватории добавлена 4 пара |
| Экзамены не помещались в сессию | Падение генератора | Жадный выбор дат заменён перебором наборов дат с откатом |

### 2026-11-08 · Просмотр без установки · GitHub Codespaces
**Инструмент:** Claude Code (+ Docker и Playwright для проверки)
**Промпт:** «Я хочу посмотреть на то, как выглядит личный кабинет, и потыкаться в него руками.
Как я могу это сделать, не скачивая весь репозиторий и не скачивая программы?»
**Как шла работа:**
1. Первая попытка — панель предпросмотра в приложении Claude: ИИ запустил кабинет и сообщил порт.
   Не сработало: в облачных сессиях предпросмотр недоступен (пользователь прислал скриншот).
2. Вторая — GitHub Codespaces: виртуальная машина в браузере. ИИ написал `.devcontainer/`
   (Node.js + PostgreSQL, установка, демо-данные, сборка, автозапуск, инструкция).
3. Проверить в настоящем Codespaces ИИ не может, поэтому **воспроизвёл его у себя**: та же конфигурация
   в Docker на чистой копии проекта — установка с нуля прошла.
4. ИИ заранее знал о подводном камне: прокси Codespaces подменяет адрес, и Next.js отклоняет формы
   как CSRF. Нашёл в документации Next.js 16 настройку `serverActions.allowedOrigins` и включил её
   только через переменную окружения (на боевом сервере защита строгая).

**Ошибки ИИ и исправления:**

| Что пошло не так | Как обнаружено | Исправление |
|---|---|---|
| Первый тест «вход через адрес Codespaces» прошёл и **без** настройки — то есть ничего не доказывал | ИИ сделал контрольный прогон «должно упасть» — а оно не упало | Браузер не даёт подменить заголовок `Origin`. Написан мини-прокси, имитирующий Codespaces, + подмена DNS в браузере. Теперь: без настройки — отказ («origin does not match»), с настройкой — вход работает |
| Тестовый запуск скрипта установки упал на первом шаге | Лог | Права на файлы в тестовой копии (в Codespaces файлы принадлежат тому же пользователю) |

5. Вопрос пользователя «придётся ли создавать Codespace заново после каждого исправления?» вскрыл
   недочёт: при повторном открытии запустилась бы **старая** версия. ИИ добавил автообновление
   (`git pull` + установка/миграции/демо-данные/сборка — только то, что изменилось) и проверил
   полный цикл в Docker: создание — 57 с; открытие без изменений — 3 с; открытие после нового коммита —
   версия обновилась.

6. **Проверка пользователем в настоящем Codespace** нашла две проблемы, которых не было в имитации:
   - ошибка 502 при открытии — помогло переподключение порта во вкладке PORTS (вероятно, вкладка
     открылась раньше, чем запустился сервер);
   - вход падал с «This page couldn't load». ИИ воспроизвёл ровно этот экран у себя: переменная
     `SERVER_ACTIONS_ALLOWED_ORIGINS` не дошла до сервера. В имитации ИИ передавал её контейнеру
     вручную, а в Codespaces с Docker Compose `containerEnv` не сработал — **имитация не повторила
     настоящий путь передачи настройки**. Исправлено: переменная задаётся в `start.sh` (при запуске)
     и в `docker-compose.yml`. Проверено, что её достаточно передать при запуске, без пересборки.
   - при повторном запуске `start.sh` — «EADDRINUSE: порт 3000 занят»: старый сервер продолжал работать
     в другом терминале. `start.sh` теперь сам останавливает прежний сервер. Первая версия шаблона
     поиска процесса в тесте «убила» сам тестовый скрипт — шаблон сужен до процессов Next.js.
   - вход всё равно падал. По логу сервера со скриншота пользователя выяснилось, что **гипотеза ИИ

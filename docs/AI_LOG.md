### 2026-11-08 · Просмотр без установки · GitHub Codespaces
**Инструмент:** Claude Code (+ Docker и Playwright для проверки)
**Промпт:** «Я хочу посмотреть на то, как выглядит личный кабинет, и потыкаться в него руками.
Как я могу это сделать, не скачивая весь репозиторий и не скачивая программы?»
**Как шла работа:**
1. Первая попытка — панель предпросмотра в приложении Claude: ИИ запустил кабинет и сообщил порт.
   Не сработало: в облачных сессиях предпросмотр недоступен (пользователь прислал скриншот).
2. Вторая — GitHub Codespaces: виртуальная машина в браузере. ИИ написал `.devcontainer/`
   (Node.js + PostgreSQL, установка, демо-данные, сборка, автозапуск, инструкция).
3. Проверить в настоящем Codespaces ИИ не может, поэтому **воспроизвёл его у себя**: та же конфигурация
   в Docker на чистой копии проекта — установка с нуля прошла.
4. ИИ заранее знал о подводном камне: прокси Codespaces подменяет адрес, и Next.js отклоняет формы
   как CSRF. Нашёл в документации Next.js 16 настройку `serverActions.allowedOrigins` и включил её
   только через переменную окружения (на боевом сервере защита строгая).

**Ошибки ИИ и исправления:**

| Что пошло не так | Как обнаружено | Исправление |
|---|---|---|
| Первый тест «вход через адрес Codespaces» прошёл и **без** настройки — то есть ничего не доказывал | ИИ сделал контрольный прогон «должно упасть» — а оно не упало | Браузер не даёт подменить заголовок `Origin`. Написан мини-прокси, имитирующий Codespaces, + подмена DNS в браузере. Теперь: без настройки — отказ («origin does not match»), с настройкой — вход работает |
| Тестовый запуск скрипта установки упал на первом шаге | Лог | Права на файлы в тестовой копии (в Codespaces файлы принадлежат тому же пользователю) |

5. Вопрос пользователя «придётся ли создавать Codespace заново после каждого исправления?» вскрыл
   недочёт: при повторном открытии запустилась бы **старая** версия. ИИ добавил автообновление
   (`git pull` + установка/миграции/демо-данные/сборка — только то, что изменилось) и проверил
   полный цикл в Docker: создание — 57 с; открытие без изменений — 3 с; открытие после нового коммита —
   версия обновилась.

**Вывод для процесса:** у каждого теста должен быть контрольный прогон, который обязан упасть, —
иначе зелёный результат может ничего не значить.
**Сделано вручную:** проверка предпросмотра в приложении (скриншот ошибки), запуск Codespace.

### 2026-11-08 · Этап 2+ · Версия для ПК, аудит безопасности, расчёт сервера
**Инструмент:** Claude Code + субагенты `security-reviewer` и `ui-reviewer` + Playwright + autocannon
**Промпт:** «Перенеси в main и покажи мне версию личного кабинета для браузера на ПК. Если ты пока
не оптимизировал интерфейс для браузера, сделай это. И ещё скажи, какие серверные мощности
понадобятся, чтобы захостить наш ЛК»
**Как шла работа:**
1. ИИ перенёс этап 2 в `main` и **параллельно** запустил субагента `security-reviewer` на код этапа 2
   (по правилу из `CLAUDE.md`), а сам занялся интерфейсом.
2. Скриншоты «до» на 1440 px показали: мобильная раскладка растянута на большой экран.
3. Новая раскладка: боковое меню, вход из двух половин, сетки, шкала статусов, выбор справки карточками.
4. ИИ сам проверил скриншоты «после» и нашёл три недочёта (обрезанное имя, фон меню на длинных
   страницах, порядок справок) и тесную форму у сотрудника — исправил.
5. Автопроверка на 360 px нашла **регресс**: горизонтальная прокрутка на странице заявок. Скрипт нашёл
   виновный элемент — длинное название справки раздвигало колонку сетки. Исправлено `grid-cols-1`,
   проверено на 6 ширинах (360–1920), правило добавлено в `DESIGN.md` и `CLAUDE.md`.
6. Аудит безопасности: утечек чужих данных нет, но найдено 5 способов испортить демо-стенд.
   Исправлены все 5 (см. таблицу), остальное записано в `ROADMAP.md`. Тестов стало 14.
7. Нагрузочный тест → расчёт сервера в `docs/DEPLOYMENT.md`. При настройке ограничения памяти ИИ
   заметил, что `docker compose` подставил `NODE_OPTIONS` из окружения машины вместо значения
   по умолчанию, — значение прописано жёстко.

**Находки `security-reviewer` и что сделано:**

| Находка | Риск для конкурса | Исправление |
|---|---|---|
| Любой может заблокировать вход в демо-аккаунты 5 неверными паролями | Критично | Лимит по паре «логин + IP»; общий по логину — 100 |
| Посетитель может сменить пароль демо-аккаунта | Критично | `DEMO_MODE`: смена пароля отключена на сервере |
| Подмена `X-Forwarded-For` обходит лимит по IP | Важно | IP только из `X-Real-IP` за доверенным прокси |
| Порт приложения открыт наружу мимо HTTPS | Важно | Порт только на `127.0.0.1` |
| Можно завалить витрину тысячами заявок | Важно | 10 активных / 5 в час на студента |
| Гонка в лимите попыток | Желательно | Попытка записывается до проверки пароля |
| Подбор текущего пароля при смене | Желательно | Тот же лимит, что у входа |
| CSP, HSTS, очистка сессий, `__Host-` cookie | Желательно | Отложено на этапы 5–6 |

**Находки `ui-reviewer` (24 замечания, 9 срочных) и что сделано:**

| Находка | Важность | Исправление |
|---|---|---|
| После ошибки в форме выделена одна справка, а отправилась бы другая; поля стирались | Критично | Форма через `onSubmit` + `startTransition` — то же правило из `CLAUDE.md`, что ИИ уже применил у сотрудника, но **не перенёс** на форму студента |
| На 1024–1190 px колонка с названием документа сжималась до 0 px | Критично | Двухколоночные страницы — с 1280 px; строки и пары «подпись — значение» перестраиваются по ширине самой карточки (container queries) |
| Тесно на 1024 px в профиле, форме заявки, у сотрудника | Важно | То же: container queries вместо брейкпоинтов экрана |
| Контраст бейджа «Готова» 3.85:1 | Важно | `--success` → `#217A36` (4.74:1) |
| Контраст текста на синей половине входа 3.0–4.2:1 | Важно | Убрана прозрачность текста, рисунок отодвинут |
| Фильтры сотрудника 40 px, счётчик 3.8:1 | Важно | 44 px, подложка счётчика темнее |
| Кнопка «Новая заявка» для скринридера — «Новая» | Важно | `sr-only` вместо `hidden` |
| На 360 px обрезалось название справки | Важно | Обрезка только в табличном виде |
| На странице 404 нет бейджа «Концепт для конкурса» | Важно | Добавлен |
| + из отложенных: порядок Tab в форме сотрудника, подписи полей с названием заявки, озвучивание этапов шкалы, имя ссылки-логотипа, нижняя панель из одного пункта, склонение «рабочих дней», порядок блоков на телефоне | Желательно | Исправлено сразу — дёшево |

Остальные 10 замечаний — в `ROADMAP.md` (этап 5).

**Проверено после исправлений:** сценарий «ошибка → исправление → отправка» создаёт выбранную справку;
ширина колонки названия ≥ 240 px на 1024–1440 px; нет горизонтальной прокрутки на 6 ширинах;
14/14 тестов; сквозной сценарий на 360 px; ограничение памяти Node.js: 290 МБ вместо 790 МБ при той же скорости.

**Вывод для процесса:** второй независимый «взгляд» (субагент-ревьюер) нашёл то, что основной агент
пропустил, хотя сам же записал правило в `CLAUDE.md`. Ревью субагентами оставляем обязательным шагом.

**Сделано вручную:** решение перенести в `main`, постановка задачи.

### 2026-11-08 · Этап 2 · Каркас, вход и безопасность
**Инструмент:** Claude Code (+ Playwright для проверки в браузере, Docker для проверки сборки)
**Задача:** проект Next.js, база данных, вход, разграничение доступа, вымышленные данные, заявки.
**Промпты:** «Перенеси в main и переходим к этапу 2. Дедлайн сдачи — 22 число, кабинет делаем
под вымышленный вуз» → (уточняющий вопрос пользователя о том, что установить на компьютер) → «Да, продолжи этап 2».
**Результат:**
- Next.js 16 + Prisma 7 + PostgreSQL, схема из 16 таблиц, миграция.
- Вход с argon2id, сессиями в базе (хранится хеш токена), ограничением 5 попыток / 15 минут.
- Слой данных с обязательным фильтром по владельцу; «контексты» студента и сотрудника.
- Страницы: вход, «Сегодня» (временная), заявки (список, подача, карточка), профиль со сменой пароля,
  кабинет сотрудника (заявки своего факультета, смена статуса → уведомление студенту).
- Seed: вымышленный Университет «Горизонт», 3 студента, 2 сотрудника, расписание на весь семестр.
- 11 автотестов безопасности, Dockerfile + docker-compose.yml.

**Ошибки ИИ и как их нашли и исправили:**

| # | Что пошло не так | Как обнаружено | Исправление |
|---|---|---|---|
| 1 | ИИ «по памяти» собирался писать код под старый Next.js | Шаблон Next.js 16 содержит `AGENTS.md`: «This is NOT the Next.js you know» | ИИ прочитал документацию из `node_modules/next/dist/docs`, выяснил, что включён новый режим `cacheComponents`, и осознанно отключил его (решение записано в `ARCHITECTURE.md`) |
| 2 | Конфликт версий при установке Vitest (`@types/node@20` против требования `^22`) | Ошибка `npm install` | Обновлён `@types/node` до 22 |
| 3 | После неверного пароля форма стирала логин — неудобно | Сквозная проверка Playwright: второй вход не срабатывал | Логин возвращается из серверного действия и подставляется в поле |
| 4 | У сотрудника после сохранения список статусов показывал старое значение | **ИИ сам заметил на скриншоте**: бейдж «В работе», а в списке «Подана» | Первая попытка (управляемые поля) не помогла — снова проверено скриншотом. Вторая: отправка через `onSubmit`, без автосброса формы React 19 |
| 5 | `next build` в Docker падал: подключение к базе создавалось при загрузке модуля | Сборка Docker-образа (на компьютере не проявлялось из-за файла `.env`) | Ленивое создание клиента Prisma в `lib/db.ts` |
| 6 | Тестовый сценарий кликал не ту кнопку (`button[type=submit]` находил «Выйти» в шапке) и ждал не тот `role="alert"` (у Next.js есть свой) | Тест «падал», хотя кабинет работал | Уточнены селекторы — ошибка была в проверке, а не в кабинете |
| 7 | Браузер получал файлы от прошлой сборки | Ошибки 500 и MIME в консоли браузера | Старый сервер не остановился; добавлено правило в `CLAUDE.md` |

**Как проверено:** `npm run lint`, `npm run typecheck`, `npm test` (11/11), `npm run build`;
сквозной сценарий в браузере на 360 px (вход → заявка → подмена адреса → 404 → сотрудник меняет статус →
студент видит «В работе»); тот же сценарий против Docker-стека.
**Сделано вручную:** выбор дедлайна и вымышленного вуза, решение продолжать в облаке.

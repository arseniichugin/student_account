# Дневник работы с ИИ

Здесь фиксируется, как проект создавался с помощью нейросетей: какие задачи ставились,
какие промпты сработали, где ИИ ошибался и как это исправлялось.
Из этого файла и папки `screenshots/` собирается итоговый отчёт для жюри.

## Как вести

После каждой заметной задачи добавляй запись по шаблону (новые — сверху):

```markdown
### ГГГГ-ММ-ДД · Этап N (или раздел) · Короткое название
**Инструмент:** Claude Code / Cursor / Kandinsky / …
**Задача:** что нужно было сделать
**Промпт:** ключевой запрос (дословно или близко к тексту)
**Результат:** что получилось, какие файлы созданы
**Ошибки ИИ и исправления:** что пошло не так и как поправили (если было)
**Сделано вручную:** что человек сделал сам
**Скриншоты:** screenshots/…
```

### 2026-11-11 · Этап 3 · Успеваемость в кабинете деканата
**Инструмент:** Claude Code — субагент-исполнитель «Деканат» (основная папка, ветка `stage-3-grades`); headless Chrome по DevTools
**Задача:** по `docs/specs/dean-grades.md` дать деканату просмотр оценок своего факультета: обзор курса с переключателем
курсов, группа, студент по номеру зачётки, поиск.
**Промпт человека:** «Деканат должен видеть оценки каждого факультета и каждого курса. По курсам деканат должен иметь
возможность переключаться… Плюс также должна быть возможность посмотреть оценки каждого студента. С привязкой к номеру
зачётки» + одобрение предложенного ИИ макета (обзор курса, таблица группы, страница студента, «Группа риска», поиск).
**Результат:** расчёт оценок семестра вынесен в чистую `buildSemesterGrades` — одна логика для студента и деканата;
`lib/data/dean-grades.ts` с фильтром по факультету из сессии и пакетной загрузкой курса (4 запроса на курс, ответы
104–153 мс в prod); сводки `lib/grades/course-stats.ts`; API поиска (401/403, до 10 подсказок, экранирование `%`/`_`);
экраны `/staff/grades` (сводка, распределение по буквам — свой SVG, группы, «Группа риска», «Заполнение журналов»),
`/staff/grades/group/[id]` (таблица «студенты × дисциплины» с липкими шапкой и колонкой; на телефоне — список),
`/staff/grades/student/[зачётка]` (те же компоненты, что у студента, только чтение); настоящий 404 для чужого факультета.
18 новых тестов, всего 202.
**Ошибки ИИ и исправления:** в меню подсвечивались и «Заявки», и «Успеваемость» → подсветка самого длинного подходящего
адреса; на 1024 px страница группы прокручивалась вбок из-за скрытых подписей для экранного диктора → `relative` у рамки
таблицы; 11 колонок из-за разных языков у соседей по группе → колонки «1-й язык» / «2-й язык»; «64 студентов» → «64
студента». Сессия оборвалась на середине работы — агент был возобновлён из сохранённого контекста и довёл задачу,
опираясь на незакоммиченные изменения в рабочем дереве.
**Сделано вручную:** уточнение требований (видимость по курсам, поиск по зачётке).

### 2026-11-11 · Этап 3 · Шкала оценок заказчика
**Инструмент:** Claude Code (оркестратор)
**Задача:** заменить взятую из интернета ECTS-таблицу на шкалу, которую утвердил заказчик.
**Промпт человека:** «Оценка А от 90 до 100, оценка Б от 82 до 89, оценка С от 65 до 81, оценка Е от 67 до 74, это оценка Д.
Оценка Е от 60 до 66, то, что ниже, оценка F. Оценки Fx и минимум также твоё предложение» (надиктовано голосом).
**Результат:** A 90–100, B 82–89, C 75–81, D 67–74, E 60–66, FX 35–59, F 0–34 — правка одного модуля

спецификации.
**Ошибки ИИ и исправления:** диктовка дала противоречие — C «от 65», а D от 67; ИИ выбрал C = 75–81 (без пересечения
с D) и записал это допущение в спецификацию и в память проекта.
**Сделано вручную:** выбор границ шкалы.

### 2026-11-11 · Этап 3 · Повторная проверка и исправление 20 замечаний двумя агентами
**Инструмент:** Claude Code — оркестратор; субагент-проверяющий (повторный запуск); исправители A «Журнал и сервер» и
B «Студент, общие экраны и документы» параллельно в отдельных git worktree со своими базами
**Промпт человека:** «Возобнови проверку агентом проверяющим. Затем исправь все те ошибки, которые он найдёт, те,
которые ты уже озвучил, и те, которые он отыщет после перезапуска».
**Как шла работа:** проверяющий подтвердил все 11 прежних замечаний и нашёл 9 новых (английская страница ошибки
Next.js при сбое базы; кнопка «Назад» молча теряла несохранённые оценки; две вкладки журнала тихо перезаписывали
чужую оценку; переключатель семестров 4-го курса на 360 px; молчаливая обрезка «1000» → «100»; 3 запроса на оценку
в транзакции и др.). Оркестратор свёл замечания в один файл и разделил их по файлам между двумя исправителями так,
чтобы они не правили одни и те же места; документы вёл только исправитель B.
**Результат:** A — лимит 60 сохранений / 1000 оценок за 10 минут; настоящий HTTP 404 через `layout.tsx` (списки
вынесены в группы `(list)`, иначе их `loading.tsx` всё равно отдавал 200); оптимистичная блокировка (`expected`) +
advisory-блокировка по дисциплине; черновики журнала в `sessionStorage`; пакетное сохранение (69 оценок: ~1,1 с →
~0,2 с); различение обрыва сети и ошибки сервера; Ctrl+S на всей странице. B — русские `app/error.tsx` и
`global-error.tsx` в цветах темы; сданный экзамен/зачёт гасит долг FX/F за срезы; seed без всплесков «ровно 60»
и «ровно 100»; прокручиваемый переключатель семестров; честный график динамики («по N из M»); ежечасное
восстановление демо-данных на сервере (`docs/DEPLOYMENT.md` §6); документы сверены с кодом.
При слиянии — один конфликт импортов в `lib/data/grades.ts`, разрешён вручную; устаревшие типы маршрутов `.next`
пересозданы `next typegen`. Итог: 183 теста в 15 файлах, сборка чистая.
**Ошибки ИИ и исправления:** исправитель A прогнал файлы через prettier, которого нет в проекте, — откатил и применил
правки заново; исправитель B попытался завершить все процессы node разом — классификатор автоматического режима это
заблокировал, дальше останавливался только свой сервер.
**Сделано вручную:** —

### 2026-11-10 · Этап 3 · Успеваемость и кабинет преподавателя: оркестрация
**Инструмент:** Claude Code (приложение для ПК) — оркестратор; три субагента-исполнителя; веб-поиск
**Задача:** раздел «Оценки» студента, кабинеты для 106 преподавателей с журналом оценок (три среза + экзамен/зачёт),
болонская шкала, статистика с графиком.
**Промпт человека:** «Нам нужно создать личные кабинеты преподавателей… у студентов должна быть функция „посмотреть
оценки“, а у преподавателей „поставить оценку“… Составь план работы… При необходимости задай мне уточняющие вопросы»
→ после ответов: «Шкала оценок болонская… Посмотри в интернете, как правильно выставляются буквы… Дальше работай как
автономный агент… Создай дополнительных агентов, которые будут выполнять различные этапы работы, а также одного
агента-проверяющего».
**Как шла работа:**
1. ИИ изучил базу SQL-запросами и нашёл опору для решений в самих данных: у каждой пары «дисциплина × группа» ровно
   один вид итогового контроля в расписании (экзамен — 275 пар, зачёт — 322) и почти всегда один семинарист (594 из 597).
2. Задал человеку 6 вопросов с вариантами по умолчанию; человек выбрал: оценки ставят только семинаристы,
   болонская шкала, «среднее из средних», демо-оценки за 1-й и половину 2-го среза, деканат — позже, с согласованием.
3. Веб-поиск показал, что единой таблицы «буква ↔ баллы» нет: вузы (РУДН, РАНХиГС, НГТУ, европейские) задают свои
   границы. Выбрана самая распространённая 100-балльная ECTS-таблица (A 90–100 … FX 35–59, F 0–34), вынесена
   в один модуль, чтобы её можно было заменить.
4. Решения записаны в спецификацию `docs/specs/grades.md` — общий документ для всех агентов.
5. Субагент «Фундамент» (база, импорт, seed, слой данных, тесты безопасности, каркас маршрутов) работал в основной
   папке; затем два UI-субагента — «Экран студента» и «Журнал преподавателя» — параллельно, каждый в своём git worktree
   со **своей базой** (`sa_ui_student`, `sa_ui_teacher`) и своим портом (3001/3002), чтобы тесты и ручные проверки
   не мешали друг другу. Оркестратор слил ветки (без конфликтов: общие файлы заранее поделены в задании).
**Ошибки ИИ и исправления:** UI-субагенты делили один встроенный браузер: вход одного агента сбрасывал вход другого,
а скрытая панель перестала отдавать кадры. Оба перешли на headless Chrome через DevTools без новых зависимостей.
Вывод на будущее: параллельным агентам — отдельные браузерные профили.
**Сделано вручную:** ответы на уточняющие вопросы и выбор шкалы.
**Скриншоты:** см. записи субагентов ниже.

### 2026-11-10 · Этап 3 · Фундамент оценок: роль преподавателя, назначения, шкала, импорт, seed
**Инструмент:** Claude Code (субагент-исполнитель в основной папке, ветка `stage-3-grades`)
**Задача:** `docs/specs/grades.md` §1–7 и §9 — роль преподавателя, назначения, новая модель оценок, импорт, seed,
слой данных с проверками доступа, каркас маршрутов для параллельной работы двух UI-агентов.
**Результат:** миграция (роль `TEACHER`, `TeachingAssignment`, новая `Grade` с проверками баллов 0–100 в самой базе,
уведомление `GRADE`); `lib/grades/scale.ts`, `lib/grades/term.ts`; 106 аккаунтов преподавателей (логин — часть почты
до `@`), 2 тестовых (`y.yudin` — экзамен, `s.semenov` — зачёт); 600 назначений; 1-й срез у всех, 2-й — у половины пар;
`requireTeacher()`, `lib/data/grades.ts` и `saveGradesAction` («всё или ничего», ошибки с номером записи); 13 тестов
безопасности (чужая группа, студент не из группы, экзамен вместо зачёта, баллы 101/−1/дробные…). 155 тестов — зелёные.
**Ключевые решения:** таблица назначений — единственный источник прав преподавателя, её строит проверка файлов, импорт
сохраняет id назначений (адреса журналов не ломаются); конфликт логинов — ошибка до изменений в базе; у экзамена
и зачёта `checkpoint = 0` в уникальном индексе; профиль преподавателя — `/teacher/profile`.
**Ошибки ИИ и исправления:** `prisma migrate dev` в неинтерактивном режиме отказался из-за потери данных → SQL через
`migrate diff`, применение через `migrate deploy`; `prisma migrate reset` заблокирован защитой Prisma от ИИ-агентов

### 2026-11-08 · Просмотр без установки · GitHub Codespaces
**Инструмент:** Claude Code (+ Docker и Playwright для проверки)
**Промпт:** «Я хочу посмотреть на то, как выглядит личный кабинет, и потыкаться в него руками.
Как я могу это сделать, не скачивая весь репозиторий и не скачивая программы?»
**Как шла работа:**
1. Первая попытка — панель предпросмотра в приложении Claude: ИИ запустил кабинет и сообщил порт.
   Не сработало: в облачных сессиях предпросмотр недоступен (пользователь прислал скриншот).
2. Вторая — GitHub Codespaces: виртуальная машина в браузере. ИИ написал `.devcontainer/`
   (Node.js + PostgreSQL, установка, демо-данные, сборка, автозапуск, инструкция).
3. Проверить в настоящем Codespaces ИИ не может, поэтому **воспроизвёл его у себя**: та же конфигурация
   в Docker на чистой копии проекта — установка с нуля прошла.
4. ИИ заранее знал о подводном камне: прокси Codespaces подменяет адрес, и Next.js отклоняет формы
   как CSRF. Нашёл в документации Next.js 16 настройку `serverActions.allowedOrigins` и включил её
   только через переменную окружения (на боевом сервере защита строгая).

**Ошибки ИИ и исправления:**

| Что пошло не так | Как обнаружено | Исправление |
|---|---|---|
| Первый тест «вход через адрес Codespaces» прошёл и **без** настройки — то есть ничего не доказывал | ИИ сделал контрольный прогон «должно упасть» — а оно не упало | Браузер не даёт подменить заголовок `Origin`. Написан мини-прокси, имитирующий Codespaces, + подмена DNS в браузере. Теперь: без настройки — отказ («origin does not match»), с настройкой — вход работает |
| Тестовый запуск скрипта установки упал на первом шаге | Лог | Права на файлы в тестовой копии (в Codespaces файлы принадлежат тому же пользователю) |

5. Вопрос пользователя «придётся ли создавать Codespace заново после каждого исправления?» вскрыл
   недочёт: при повторном открытии запустилась бы **старая** версия. ИИ добавил автообновление
   (`git pull` + установка/миграции/демо-данные/сборка — только то, что изменилось) и проверил
   полный цикл в Docker: создание — 57 с; открытие без изменений — 3 с; открытие после нового коммита —
   версия обновилась.

6. **Проверка пользователем в настоящем Codespace** нашла две проблемы, которых не было в имитации:
   - ошибка 502 при открытии — помогло переподключение порта во вкладке PORTS (вероятно, вкладка
     открылась раньше, чем запустился сервер);
   - вход падал с «This page couldn't load». ИИ воспроизвёл ровно этот экран у себя: переменная
     `SERVER_ACTIONS_ALLOWED_ORIGINS` не дошла до сервера. В имитации ИИ передавал её контейнеру
     вручную, а в Codespaces с Docker Compose `containerEnv` не сработал — **имитация не повторила
     настоящий путь передачи настройки**. Исправлено: переменная задаётся в `start.sh` (при запуске)
     и в `docker-compose.yml`. Проверено, что её достаточно передать при запуске, без пересборки.
   - при повторном запуске `start.sh` — «EADDRINUSE: порт 3000 занят»: старый сервер продолжал работать
     в другом терминале. `start.sh` теперь сам останавливает прежний сервер. Первая версия шаблона
     поиска процесса в тесте «убила» сам тестовый скрипт — шаблон сужен до процессов Next.js.
   - вход всё равно падал. По логу сервера со скриншота пользователя выяснилось, что **гипотеза ИИ
     была неверной**: Codespaces подменяет не адрес сервера, а заголовок `Origin` (на `localhost:3000`).
     ИИ строил имитацию по описанию проблемы из памяти, а не по реальным данным. Имитация
     переделана по реальному логу — ошибка воспроизведена дословно; исправление (разрешить и
     `localhost:3000`) проверено на ней.
   - и снова не помогло: в контейнере осталось старое значение переменной из прошлой версии, а скрипт
     задавал её только «если не задана». Ошибка была видна в строке запуска «Формы принимаются с адресов:
     *.app.github.dev» — диагностическая строка, добавленная шагом раньше, окупилась сразу.
     Теперь значение задаётся всегда; проверено именно с заранее заданным старым значением.

**Вывод для процесса:** имитацию внешней среды строить по реальным логам, а не по памяти; и у каждого теста должен быть контрольный прогон, который обязан упасть, —
иначе зелёный результат может ничего не значить.
**Сделано вручную:** проверка предпросмотра в приложении (скриншот ошибки), запуск Codespace.

# Оценки на занятиях

Текущая успеваемость: оценки, которые студент получает на конкретных занятиях, вкладка «Оценки»
с инфографикой у студента и окно ввода оценок у деканата.

> Сейчас оценки выставляет **деканат** (`/staff/marks`). Когда появится роль преподавателя,
> ей достаточно дать тот же слой данных `lib/data/marks.ts` с проверкой «занятие ведёт этот преподаватель».

## Что было и что добавлено

В базе уже была таблица `Grade` — **итоговые оценки ведомостей**: экзамен, зачёт, курсовая, контрольная точка
за семестр (одна запись на дисциплину и вид контроля). Оценок за отдельные занятия не было.

Добавлена таблица **`Mark` — оценка на занятии**. На одном занятии у студента может быть
**сколько угодно оценок, в том числе ни одной** (ограничение-предохранитель — 10, `MAX_MARKS_PER_LESSON`).

```
Mark   id, studentId → Student (каскад)
       lessonId? → Lesson (SetNull), lessonOid — oid занятия из schedule.csv
       disciplineId → Discipline, date (@db.Date, по Москве), startTime «10:30», lessonKind «Семинар»
       value 1–5, createdById? → Staff (SetNull; null — демо-наполнение), createdAt
       индексы: (studentId, date), lessonId, lessonOid, (createdById, createdAt)
```

**Почему дата, дисциплина и время скопированы в оценку.** Импорт расписания (`npm run data:import`) удаляет
и пересоздаёт все занятия. Связь `lessonId` при этом обнуляется (`onDelete: SetNull`), а сразу после создания
новых занятий импорт восстанавливает её одним запросом по `lessonOid`
(`lib/university-data/import.ts`). Если занятие исчезло из нового расписания, оценка не пропадает:
дата, предмет и время остаются в ней самой. Дисциплина с оценками при импорте не удаляется.

Миграция: `prisma/migrations/20261117105754_lesson_marks`.

## Тестовые данные

`npm run db:seed` (входит в `db:setup` и `db:reset`) создаёт оценки **для всех студентов** по всем
**прошедшим на день запуска** (по Москве) и не отменённым занятиям их групп — академической и языковых:

| Вид занятия | 0 оценок | 1 | 2 | 3 |
|---|---|---|---|---|
| Семинар, практическое и др. | 50 % | 35 % | 12 % | 3 % |
| Лекция | 93 % | 7 % | — | — |

У каждого студента свой «уровень» (сильный / средний / слабый) — он задаёт, какие оценки ставят чаще;
студенты с долгом (например, тестовый `eva.orlova25`) — всегда «слабые». Случайность детерминирована
(зависит от ID студента и занятия), так что повторный запуск в тот же день даёт тот же результат.
На основном наборе данных 17.11.2026 — около **87 тыс.** оценок. Демо-оценки создаются с `createdById = null`,
поэтому в списке «Последние выставленные» у деканата видны только оценки, введённые через форму.

> Демо-стенд должен работать до 28 ноября: чтобы в блоке «за неделю» были свежие оценки,
> перезапускайте `npm run db:seed` перед показом (оценки за прошедшие с прошлого запуска дни добавятся).

## Студент: вкладка «Оценки» (`/grades`)

Пункт «Оценки» в меню (`lib/navigation.ts`), страница `app/(app)/(student)/grades/` (`requireStudent`),
данные — `getMyMarksOverview(ctx)`; оценки берутся **только** по `ctx.studentId` из сессии.

| Блок | Что показывает | Как считается |
|---|---|---|
| **Средний балл за всё обучение** | одно число + сколько оценок | все числовые оценки студента: на занятиях (`Mark`) и в ведомостях (`Grade` со значением 1–5; «зачтено» не учитывается) |
| **Средний балл за семестр** | одно число | то же, но только оценки текущего семестра |
| **За последнюю неделю** | средний балл + список | оценки на занятиях за последние 7 дней (сегодня включительно), по дням, новые сверху |
| **Средний балл по семестрам** | столбчатая диаграмма, шкала 0–5 | по семестрам с 1-го по текущий; текущий — яркий столбец; для скринридера — скрытая таблица |
| **Оценки на занятиях в семестре** | сколько «5», «4», «3», «2», «1» | полосы + количество и процент |
| **По предметам** | средний по предмету и все оценки по порядку | при наведении — дата, время и вид занятия |

**Семестр.** Учебный год начинается 1 сентября; осенний семестр — сентябрь…январь, весенний — февраль…август
(`lib/marks/stats.ts`). Номер семестра студента выводится из курса: 3 курс осенью — 5 семестр,
весна прошлого учебного года — 4 и т. д. Номер семестра оценки ведомости берётся из `Grade.semester`.

Состояния: загрузка — `loading.tsx` (скелетон); пусто — «Оценок пока нет» со ссылкой на расписание;
ошибка — общий `app/(app)/error.tsx` с кнопкой «Повторить». Пустая неделя и пустой семестр — свои пояснения.

## Деканат: окно ввода оценок (`/staff/marks`)

Пункт «Оценки» в меню сотрудника. Форма из четырёх полей:

| Поле | Подсказки при наборе (не больше 5) | Что набирать |
|---|---|---|
| **Студент** | студенты **своего факультета**: по началу фамилии, имени, отчества, группы или логина; можно несколько слов («Шарова Лар», «1-ГР-1 Ива») | от 2 символов |
| **Предмет** | дисциплины, по которым у студента **уже были** занятия; рядом — сколько у него оценок по предмету | часть названия; при фокусе — первые 5 |
| **Дата занятия** | прошедшие занятия студента по предмету, сначала последние: «13.11.2026, 09:00 · Практическое занятие · уже: 5» | «12», «12.11», «12.11.2026», «2026-11»; при фокусе — 5 последних |
| **Оценка** | 5 кнопок: 5, 4, 3, 2, 1 | — |

- Следующее поле открывается, когда выбрано предыдущее; смена студента сбрасывает предмет и дату.
- В форму уходят только id из подсказок (свободный текст не принимается) — сервер всё равно проверяет их заново.
- Если в один день две пары по предмету, в подсказках будут два занятия с разным временем.
- После сохранения студент и предмет остаются в форме — удобно ставить оценки подряд;
  в подсказке даты сразу видно «уже: 5, 4».
- Клавиатура: ↑/↓ — выбор, Enter — выбрать, Esc — закрыть список; у поля — `role="combobox"` и `aria-activedescendant`.
- Справа — «Последние выставленные» (10 оценок деканата факультета) с кнопкой удаления на случай ошибки.

Компонент подсказок — `components/ui/combobox.tsx` (переиспользуемый: адрес подсказок передаётся функцией `url(q)`).

### API подсказок

`GET /api/staff/marks/suggest` — только для сотрудника (`getStaffContext`; без сессии и для студента — **401**),
ответ `{ results: { id, label, meta }[] }`, не больше 5 элементов, `Cache-Control: private, no-store`.

| Параметры | Ответ |
|---|---|
| `field=student&q=Шар` | студенты своего факультета |
| `field=discipline&student=<id>&q=зель` | предметы студента |
| `field=lesson&student=<id>&discipline=<id>&q=12.11` | прошедшие занятия студента по предмету |

Студент чужого факультета → пустой список (тот же ответ, что и для несуществующего).

### Правила на сервере (`lib/data/marks.ts`)

`createFacultyMark(ctx: StaffContext, …)` выставляет оценку, только если:

1. студент учится на факультете сотрудника (`facultyId = ctx.facultyId`);
2. занятие — в одной из групп **этого** студента (академической или языковой);
3. занятие уже было (дата ≤ сегодня по Москве) и не отменено;
4. оценка — целое 1–5 (Zod, `lib/validation/marks.ts`), на занятии меньше 10 оценок студента.

`deleteFacultyMark` удаляет только оценку студента своего факультета. Демо-режим не ограничивает ввод:
оценки не «ломают» общий демо-аккаунт и удаляются кнопкой.

## Тесты

`tests/marks.test.ts` (нужна база после `npm run db:setup`):
- семестры, номер семестра студента, средние, разбор дат «12.11» — чистые функции;
- у студента есть обзор, в нём только его оценки;
- несколько оценок на одном занятии сохраняются и попадают к студенту;
- деканат другого факультета не может поставить, найти в подсказках или удалить оценку;
- нельзя поставить оценку за чужое занятие и за занятие в будущем;
- подсказок не больше 5 и только по прошедшим занятиям.

`tests/university-import.test.ts`: после повторного импорта число оценок на занятиях то же, и у всех восстановлена связь с занятием.
`tests/schedule-ui.test.ts`: в меню новые пункты; на `/staff/marks` подсвечивается «Оценки», а не «Заявки».

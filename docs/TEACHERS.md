# Кабинет преподавателя

Третья роль кабинета: **преподаватель** (`TEACHER`). Вместе со студентом и деканатом получается
полный цикл: деканат и преподаватели выставляют оценки и пишут сообщения, студенты получают их.

| | Студент | Преподаватель | Деканат |
|---|---|---|---|
| Расписание | своё | **своё** (все его группы) | любой группы |
| Оценки | смотрит свои | **ставит своим группам за свои занятия** | ставит студентам факультета |
| Уведомления | получает | **получает и пишет своим группам** | пишет студентам и преподавателям |
| Заявки и справки | подаёт | **нет раздела** | обрабатывает |

## Распределение групп по преподавателям

**Правило:** у пары (группа, дисциплина) один преподаватель на весь учебный год, а у преподавателя
может быть сколько угодно групп одновременно.

В исходном расписании правило нарушалось у 295 пар из 597. Распределение выполнил отдельный
субагент Claude Code: он написал детерминированный скрипт
[`tools/teacher-assignment/assign_teachers.py`](../tools/teacher-assignment/README.md) и переписал
им колонки преподавателя в `data/university/schedule.csv`. Остальные колонки не менялись.

| | Было | Стало |
|---|---|---|
| Пар с несколькими преподавателями | 295 | 0 (+19 исключений потоков, см. ниже) |
| Накладок «два занятия одновременно» | 5 | 0 |
| Групп у преподавателя (мин / медиана / макс) | 1 / 7 / 33 | 2 / 5 / 15 |
| Нагрузка в занятиях (мин / медиана / макс) | 1 / 233 / 336 | 65 / 215 / 262 |

Как это сделано:
- преподаватель ведёт только те дисциплины, которые уже вёл, кроме 4 случаев (описаны в README скрипта);
- предпочтение отдаётся тому, кто уже вёл большинство занятий пары;
- у лекции потока один преподаватель на все группы потока.

**Исключения (19 пар).** В некоторых потоках две группы одновременно занимаются одной дисциплиной
в разных аудиториях. Один преподаватель на такой поток физически невозможен. В этих случаях лекцию
потока ведёт лектор потока, а все остальные занятия группы — один другой преподаватель.
Чтобы убрать исключения совсем, нужно менять время занятий в генераторе расписания.

Проверки:
- `python3 tools/teacher-assignment/assign_teachers.py --check` — скрипт;
- `tests/teachers.test.ts` — по базе: у пары не больше одного преподавателя на всех занятиях, кроме лекций,
  и не больше двух с лекциями.

## Аккаунты

Аккаунты преподавателей создаёт **импорт** (`npm run data:import`), как и аккаунты деканатов:

- **логин** — часть почты до «@»: `s.romanov@hogwarts.example.org` → `s.romanov`. Без почты логин
  получается транслитом краткого ФИО. Если логин уже занят студентом или сотрудником, добавляется суффикс `.t`;
- **пароль** — общий `DEMO_PASSWORD` (по умолчанию `Hogwarts2026`) только у **тестовых**
  преподавателей (`isDemo`), по одному на каждого тестового студента. Остальные получают **случайный пароль**
  при создании аккаунта, а повторный импорт его не меняет. Иначе по опубликованному паролю можно было бы
  войти под любым преподавателем: логин — это часть почты из расписания (замечание `security-reviewer`);
- тестовые преподаватели выбираются автоматически (`pickTestTeachers`): для каждого тестового студента —
  из тех, кто ведёт занятия у его академической группы, с наибольшим числом групп (при равенстве — по oid);
  уже выбранный второй раз не берётся — тогда следующий кандидат. Так цепочку «преподаватель ставит оценку /
  пишет группе → студент видит» можно пройти на каждом тестовом студенте;
- переменная `TEST_TEACHER_LOGINS=логин1,логин2` заменяет автоматический выбор (неизвестный логин — ошибка
  импорта, база не меняется; преподаватель без групп тестовых студентов — предупреждение);
- если тестовый меняется, бывший получает новый случайный пароль, а его сессии закрываются;
- логины и пароли попадают в `credentials.csv` с ролью «Преподаватель» (тестовые — «Преподаватель (тестовый)»);
- если преподаватель исчез из расписания, его аккаунт удаляется при следующем импорте.

тестовых аккаунтов:

|---|---|---|---|

## Что видит преподаватель

Меню: **Расписание · Журнал · Рассылка · Карта**. В шапке — колокольчик с числом непрочитанных.
Главная страница — расписание.

### Расписание (`/schedule`)
Без параметров показывает «Моё расписание»: все занятия преподавателя со списком групп.
Поиск по любой группе или преподавателю работает, как у остальных ролей.

### Журнал (`/teacher/marks`): оценки и посещаемость

Журнал в виде таблицы:
- **выбор** — пары «группа + предмет», которые он ведёт (лента сверху, с числом прошедших занятий);
- **строки** — студенты группы (академической или языковой);
- **столбцы** — его начавшиеся неотменённые занятия у этой группы, хронологически слева направо;
  по умолчанию последние 8, кнопка «Все занятия (N)»;
- **клетка** — оценки и отметка посещаемости: `✓` был, `оп` опоздал, `н` не был, `·` пусто;
- **панель клетки** открывается по нажатию на клетку (на телефоне — над таблицей, на компьютере — справа):
  - добавить оценку 5–1, можно несколько на одном занятии;
  - удалить свою оценку; оценку деканата преподаватель не удаляет, она помечена «деканат»;
  - посещаемость: «Был», «Опоздал», «Не был», «Снять отметку» (одна отметка на студента и занятие).

**Всё работает без JavaScript.** Выбор группы и клетки — обычные ссылки, кнопки — обычные формы с серверными
действиями (`lib/journal/actions.ts`). После сохранения действие возвращает на ту же страницу с открытой клеткой.
Это сделано специально: на стенде бывало, что JS не загружался (`docs/DEPLOYMENT.md` §7). Каждая кнопка проверена
Playwright в трёх режимах: телефон, компьютер, заблокированные `/_next/static/*.js`; изменения проверены в базе.

Права — те же, что у оценок (`Grader` в `lib/data/marks.ts`), плюс `lib/data/journal.ts`:
- чужая пара «группа + предмет» даёт «Журнал не найден»;
- посещаемость отмечается только своему студенту за своё начавшееся занятие.

После сохранения действие возвращает на страницу через `redirect`. Адрес возврата проверяется: только `/teacher/marks…`
(`safeJournalBack`). Ошибка передаётся в адресе **кодом** (`?msg=mark`), а текст берётся из справочника
(`JOURNAL_MESSAGES`), поэтому чужая ссылка не может показать на странице свой текст.

Посещаемость хранится в таблице `Attendance` (миграция `20261117170000_attendance`):

```
Attendance  studentId, lessonId? (SetNull) + lessonOid, date, status (PRESENT | LATE | ABSENT), teacherId?, updatedAt
            уникально (studentId, lessonOid)
```

Повторный импорт расписания, как и для оценок, заново привязывает отметки к занятиям по `lessonOid`.
Демо-наполнение отмечает посещаемость всех прошедших занятий, около 168 тыс. отметок. Кто получил оценку,
тот был на занятии; у студентов с долгом пропусков больше.

### Рассылка (`/teacher/notifications`)
Форма события: вид, название, текст, когда (сейчас или по расписанию). Кому:
- **Всем моим группам** — студентам всех групп, у которых он ведёт занятия;
- **Отправить группе…** — подсказки только из его групп (`GET /api/teacher/groups`).

Рядом — запланированные и отправленные события со счётчиком «прочитали N из M» и отменой.
События преподавателя не привязаны к факультету: деканат их не видит и не отменяет,
другой преподаватель тоже.

### Уведомления (`/notifications`)
Общая страница для студента и преподавателя (`requireRecipient`). У каждого уведомления видно,
от кого оно: «Деканат», «Преподаватель Черных В.А.», а у автоматических (статус заявки) — ничего.

### Чего у преподавателя нет
Заявок и справок: пункта нет в меню, а страницы студента (`requireStudent`) и деканата
(`requireStaff`) перенаправляют преподавателя на его главную. Профиля и страницы «Сегодня» пока нет.

### Профиль (`/teacher/profile`)

ФИО, звание, дисциплины и группы (по расписанию), почта, логин; «О себе» и смена пароля (у тестовых аккаунтов — объяснение
вместо формы). «О себе» преподавателя студенты и деканат видят на странице его расписания (`/schedule?teacher=…`, блок «О преподавателе»).

## Новое у деканата

В форме события (`/staff/notifications`) появились два варианта «Кому отправить»:
- **Всем преподавателям (N)** — всем, кто ведёт занятия у групп факультета;
- **Преподавателю…** — подсказки из тех же преподавателей (`GET /api/staff/notifications/teachers`).

Деканат по-прежнему работает только со своим факультетом: преподавателю, который не ведёт
занятий у факультета, написать нельзя.

## Кружки на «Оценках» и «Заявках» у студента

- **Оценки** — число оценок, выставленных после того, как студент последний раз открывал раздел
  (`Student.marksSeenAt`). На странице новые помечены «Новая».
- **Заявки** — число заявок, у которых деканат изменил статус, а студент ещё не видел
  (`Request.statusSeen`, сбрасывается при смене статуса). В списке они помечены «Статус изменился».
- Открытие раздела убирает кружок, а подсветка остаётся до следующего открытия (`components/mark-seen.tsx`).
- Кружок на телефоне — красное число на иконке нижней панели, на компьютере — число справа
  от пункта бокового меню.

## Модель данных

Миграции `20261117131019_seen_badges` и `20261117133000_teachers`:

```
Role               + TEACHER
Teacher            + userId? → User (уникальный; аккаунт преподавателя)
Mark               + teacherId? → Teacher (кто выставил, если преподаватель)
Announcement       + audience (FACULTY | COURSE | GROUP | ALL_TEACHERS | TEACHER | MY_GROUPS)
                   + teacherId? → Teacher (для «Преподавателю…»)
Student            + marksSeenAt (кружок «новые оценки»)
Request            + statusSeen (кружок «статус изменился»)
```

## Безопасность

- `TeacherContext` создаётся только из сессии (`requireTeacher` / `getTeacherContext` в `lib/auth/guards.ts`).
- Группы преподавателя всегда вычисляются на сервере по расписанию (`teacherGroupIds`),
  а не берутся из формы.
- Чужой студент, чужая группа или чужое событие дают тот же ответ, что и несуществующие.

`tests/teachers.test.ts` проверяет:
- аккаунты: у каждого преподавателя есть аккаунт, логины уникальны;
- распределение групп по преподавателям;
- оценки: только свои группы, только свои занятия, удаление только своих;
- рассылку: только своим группам, нельзя «всем студентам факультета»;
- что деканат и другой преподаватель не видят и не отменяют чужое событие;
- что «всем преподавателям» и «преподавателю…» доходят до преподавателя и не доходят до студентов.

## Тестовые данные

`npm run db:seed`:
- **оценки на занятиях** записаны на преподавателя занятия (`teacherId`) и «выставлены» после конца пары;
  учитываются только уже закончившиеся пары;
- **«последний раз открывал оценки»** — двое суток назад, поэтому у студентов 2–3 новые оценки;
- **заявки**: со статусом «готова», «в работе» или «отклонена» — непросмотренные;
- **событие деканата «Ведомости зимней сессии»** — всем преподавателям факультета;
- **сообщение преподавателя «… контрольная работа»** — группе первого тестового студента.

# Развёртывание и серверные мощности

## 1. Замеры (8 ноября 2026)

Продакшен-сборка, один процесс Next.js, PostgreSQL на той же машине, 4 vCPU Intel Xeon 2.3 ГГц.
Нагрузка — `autocannon`, 20 одновременных подключений, 15 секунд на страницу, вошедший студент.

| Что | Результат |
|---|---|
| Страница входа | ~210 запросов/с, задержка ~95 мс |
| «Сегодня» (запросы к базе) | ~145 запросов/с, ~135 мс |
| «Заявки» (запросы к базе) | ~140 запросов/с, ~145 мс |
| Проверка пароля argon2id | ~10 мс; ~350 входов/с на 4 ядрах |
| Память Node.js | 280 МБ в покое → ~790 МБ под нагрузкой (без ограничения) |
| Память PostgreSQL | ~250 МБ |
| Размер базы с демо-данными | ~9 МБ |

Один процесс Node.js использует в основном **одно ядро**, поэтому ~140 запросов/с — это
производительность одного ядра. Масштабируется добавлением процессов/серверов: сессии хранятся
в базе, приложение не хранит состояние в памяти.

## 2. Сколько это пользователей

Студент за один визит открывает ~5 страниц. Утренний пик: допустим, 20 % студентов заходят за 10 минут.

| Студентов в вузе | Пиковая нагрузка | Хватит |
|---|---|---|
| Жюри конкурса (десятки человек) | < 1 запроса/с | 1 процесс, загрузка ~1 % |
| 5 000 | ~8 запросов/с | 1 процесс |
| 30 000 | ~50 запросов/с | 1 процесс на пределе комфорта → 2 процесса для запаса и отказоустойчивости |
| 100 000 | ~170 запросов/с | 3–4 процесса + отдельный сервер базы |

Это оценка по замерам на демо-данных; для настоящего вуза нужен нагрузочный тест на реальных объёмах.

## 3. Рекомендуемый сервер для конкурса

| Параметр | Минимум | Рекомендуется |
|---|---|---|
| vCPU | 1 | **2** |
| RAM | 2 ГБ + swap 2 ГБ | **4 ГБ** |
| Диск | 20 ГБ SSD | **30–40 ГБ NVMe** |
| ОС | Ubuntu 24.04 LTS | Ubuntu 24.04 LTS |
| Сеть | публичный IPv4 | публичный IPv4 |

Почему 4 ГБ, а не 2: сама работа укладывается в ~1 ГБ (приложение ≤ 512 МБ с ограничением
`NODE_OPTIONS`, PostgreSQL ~250 МБ, Caddy ~30 МБ), но **сборка** Docker-образа (`next build`)
кратковременно требует 1,5–2 ГБ. С 2 ГБ сборка возможна только со swap.

Провайдеры с дата-центрами в России (доступ без VPN): Timeweb Cloud, Yandex Cloud, Selectel, VK Cloud.
Сервер нужен оплаченным **до 28 ноября** включительно.

## 4. Масштаб «настоящего вуза» (для описания проекта)

```
           ┌──────────── балансировщик (HTTPS) ────────────┐
           ▼                       ▼                        ▼
   приложение #1 (2 vCPU/2 ГБ)  приложение #2  …  приложение #N
           └───────────────┬───────────────────────────────┘
                           ▼
        управляемый PostgreSQL (2–4 vCPU, 8 ГБ) + реплика + бэкапы
```

- Приложение без состояния → добавляем копии под нагрузку.
- Управляемая база (Yandex Managed PostgreSQL и т. п.) — бэкапы и реплики «из коробки».
- Тяжёлая операция — только вход (argon2): ~350 входов/с на 4 ядрах с запасом покрывают пиковые утренние волны.

## 5. Шаги развёртывания (этап 6)

1. Арендовать VPS, установить Docker и Caddy.
2. `git clone`, создать `.env`: длинный случайный `POSTGRES_PASSWORD`, свой `SEED_DEMO_PASSWORD`.
3. `docker compose run --rm migrate` — таблицы и демо-данные.
4. `docker compose up -d app` — приложение (слушает только `127.0.0.1:3000`).
5. Caddy: домен → `reverse_proxy 127.0.0.1:3000`, `header_up X-Real-IP {remote_host}`; HTTPS и HSTS.
6. Проверить с телефона через мобильный интернет без VPN, вписать ссылку и пароль в README.
7. Cron: ночное пересоздание демо-данных, ежедневный бэкап базы (`pg_dump`).

# Уведомления: события деканата

> Обновление 21.11: деканатский вариант **«Отправить всем»** — это студенты факультета **и** преподаватели, которые ведут
> занятия у его групп (раньше — только студенты). «Курсу» и «группе» — по-прежнему только студенты.
>
> Обновление: уведомления получают и **преподаватели**, деканат может написать «всем преподавателям»
> и «преподавателю …», а преподаватель — своим группам. Подробно — `docs/TEACHERS.md`.

Деканат создаёт **событие**: сообщение, дату экзамена, срок сдачи или изменение расписания.
Студенты получают его в разделе «Уведомления», а на колокольчике в шапке появляется число непрочитанных.
**Создавать события может только деканат.** Студенты только читают.

## Модель данных

Таблицы `Announcement` и `Notification` были в схеме и раньше, но интерфейса у них не было.
Миграция `prisma/migrations/20261117124738_staff_notifications` добавила к ним:

```
Announcement   + kind (вид события, тип NotificationType), + createdAt
               publishedAt — ВРЕМЯ ОТПРАВКИ (может быть в будущем)
               facultyId / course / groupId — аудитория
Notification   + announcementId? → Announcement (каскад: отмена события удаляет уведомления)
               createdAt — момент, с которого уведомление видно студенту
NotificationType + EXAM
```

**Как устроена отправка.** При создании события сразу определяются получатели, и каждому создаётся
своя запись `Notification` с `createdAt` = время отправки. Студент видит уведомления только с
`createdAt ≤ сейчас`, поэтому отложенная отправка работает **без фоновых задач и cron**: в нужный момент
уведомление просто становится видимым. Отменить отложенное событие можно до отправки, а отправленное —
удалить у всех получателей.

> Получатели фиксируются при создании. Если студент перейдёт в группу после того, как событие
> запланировали, это событие он не получит.

## Деканат: вкладка «Уведомления» (`/staff/notifications`)

Пункт меню «Уведомления» (`lib/navigation.ts`), страница `app/(app)/(staff)/staff/notifications/` (`requireStaff`).

| Поле | Варианты |
|---|---|
| **Вид события** | Сообщение деканата · Экзамен · Срок сдачи · Изменение расписания |
| **Название** | 3–120 символов |
| **Текст сообщения** | 1–2000 символов, со счётчиком |
| **Кому отправить** | **Отправить всем** (все студенты факультета, рядом их число) · **Отправить курсу…** (список курсов с числом студентов) · **Отправить группе…** (поле с подсказками: до 5 групп факультета, академических и языковых, с числом студентов) |
| **Когда отправить** | **Сейчас** · **Запланировать** — дата и время по Москве |

- «Всем» означает всех студентов **своего** факультета: деканат работает только со своим факультетом,
  как и с заявками. Событие для всего вуза пока создаёт только демо-наполнение.
- После отправки очищаются название и текст, а вид и аудитория остаются: удобно отправлять серию.
- Ошибки показываются под полями (`aria-invalid`, `aria-describedby`).
- Справа — **«Запланированные»** (ближайшие сверху) и **«Отправленные»** (новые сверху), у отправленных
  есть счётчик «Прочитали N из M». Кнопка с корзиной отменяет отправку или удаляет событие у всех получателей,
  с подтверждением.

### Правила на сервере (`lib/data/notifications.ts`)

`createFacultyAnnouncement(ctx: StaffContext, …)`:
1. автор и факультет берутся из сессии, а не из формы;
2. получатели — только студенты факультета сотрудника; группа должна принадлежать этому факультету
   (группа чужого факультета → «Группа не найдена», в подсказках её тоже нет);
3. время отправки — не в прошлом (запас 10 минут, иначе ошибка) и не дальше 180 дней вперёд;
4. не больше 20 событий в час на сотрудника — защита общего демо-аккаунта деканата от спама;
5. пустая аудитория → ошибка «В выбранной аудитории нет студентов».

`deleteFacultyAnnouncement` и `listFacultyAnnouncements` работают только с событиями своего факультета.

### API подсказок групп

`GET /api/staff/notifications/groups?q=1-ГР` — только для сотрудника (`getStaffContext`, иначе **401**),
отдаёт не больше 5 групп своего факультета: `{ results: { id, label, meta }[] }`, `Cache-Control: private, no-store`.

## Студент: колокольчик и раздел «Уведомления» (`/notifications`)

- **Колокольчик** в шапке (телефон) и пункт «Уведомления» в боковом меню (компьютер). Красная цифра —
  число непрочитанных уже пришедших уведомлений (`countMyUnreadNotifications`). В нижнюю панель
  пункт не добавлен: в ней уже 6 разделов.
- **Страница** — все пришедшие уведомления, новые сверху: вид (иконка и подпись), время, название, текст.
  Непрочитанные выделены рамкой и меткой «Новое». Уведомление о заявке ведёт на её карточку
  (в ссылки попадают только внутренние адреса `/…`).
- Открытие страницы отмечает уведомления прочитанными (`markMyNotificationsRead`), а метка «Новое»
  остаётся до следующего открытия. Ещё не пришедшие (запланированные) не затрагиваются.
- Состояния: скелетон (`loading.tsx`), пусто («Уведомлений пока нет» и кнопка «На главную»),
  ошибка — общий `app/(app)/error.tsx`.

Здесь же видны уведомления, которые создаются автоматически: смена статуса заявки (`lib/data/requests.ts`),
а также сроки сдачи и изменения расписания из демо-наполнения.

## Тестовые данные

`npm run db:seed` рассылает демо-события деканатов (график сессии — вид «Экзамен», посвящение
для 1 курса, выбор темы ВКР для старшего курса, неделя открытых библиотек — для всех) **всем получателям**,
как это делает кабинет: около 2,5 тыс. уведомлений. Примерно 60 % из них отмечены прочитанными,
а у тестовых студентов всё непрочитано, чтобы на колокольчике была цифра.

## Тесты

`tests/notifications.test.ts`:
- форма (Zod): курс обязателен для «курсу», группа — для «группе», время — для «запланировать»;
- «всем» — ровно студенты своего факультета; студент другого факультета ничего не получает;
- «группе» и «курсу» — ровно нужные студенты;
- группе чужого факультета отправить нельзя, в подсказках её нет; подсказок ≤ 5;
- отложенное событие не видно до времени отправки, потом появляется; «прочитать всё» его не трогает;
- время в прошлом и дальше 180 дней отклоняется;
- чужой деканат не видит и не отменяет событие; свой отменяет вместе с уведомлениями;
- студент видит только свои уведомления.

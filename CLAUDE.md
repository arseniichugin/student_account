# CLAUDE.md — правила проекта для ИИ-ассистентов

Этот файл читают ИИ-ассистенты (Claude Code и другие) перед любой работой с репозиторием.
Если правило здесь противоречит запросу — уточни у человека, а не нарушай молча.

## О проекте

**«Цифровой деканат будущего»** — прототип личного кабинета студента для конкурса.
Вуз вымышленный: **«Хогвартс»** (4 факультета, 990 студентов, расписание на семестр).
Все данные вуза — в **заменяемых файлах** `data/university/` (формат — `data/university/README.md`);
кабинет не должен зависеть от конкретных факультетов, групп и дисциплин.
Это концепт, а не официальный сервис вуза. **Дедлайн сдачи — 22 ноября 2026**, прототип должен работать до 28 ноября.

## Стек

Next.js 16 (App Router) + TypeScript · React 19 · Tailwind CSS 4 · PostgreSQL 16 + Prisma 7 ·
сессии в `httpOnly` cookie · argon2id · Zod · Vitest · Docker Compose · VPS в российском облаке.
Не добавляй новые крупные зависимости без объяснения, зачем они нужны.

### Особенности версий (важно — отличаются от старых примеров в интернете)

- **Next.js 16** сильно отличается от 13–15. Перед работой с незнакомым API читай документацию
  в `node_modules/next/dist/docs/` (см. `AGENTS.md`). Middleware называется `proxy.ts`.
- **`cacheComponents` выключен намеренно** (`next.config.ts`): все страницы кабинета зависят
  от сессии. Не включай и не используй `"use cache"` без обсуждения.
- **`params` и `searchParams` — промисы**: `const { id } = await params`. Типы страниц —
  глобальные `PageProps<"/путь">` и `LayoutProps<"/">`.
- **Prisma 7**: настройки подключения — в `prisma.config.ts`, а не в `schema.prisma`.
  Клиент генерируется в `lib/generated/prisma` (не коммитится), импорт —
  `@/lib/generated/prisma/client`, перечисления для клиентских компонентов — `@/lib/generated/prisma/enums`.
- **React 19 и формы**: `<form action={...}>` после отправки сбрасывает поля к начальным значениям.
  Для форм, где после сохранения поля должны показывать новые значения, используй
  `onSubmit` + `startTransition(() => formAction(formData))` (пример — `app/(app)/(staff)/staff/status-form.tsx`).

## Жёсткие правила (нарушать нельзя)

1. **Только вымышленные данные.** Никаких реальных ФИО, оценок, номеров зачёток, логинов.
   Не подключаться к настоящим системам вуза. Парсинг открытых данных (расписание) — можно.
2. **Студент видит только свои данные; преподаватель — только свои группы** (по `TeachingAssignment`). Любой запрос к данным студента фильтруется
   по `studentId` из сессии, а не по параметру из URL или тела запроса:
   ```ts
   // ❌ id из адреса без проверки владельца
   db.request.findUnique({ where: { id } })
   // ✅ ищем только среди своих
   db.request.findFirst({ where: { id, studentId: session.studentId } })
   ```
   Права проверяются **на сервере**. Скрытая кнопка в интерфейсе — не защита.
3. **Пароли — только хеш argon2.** Никогда не логировать пароли и токены.
4. **Секреты — только в переменных окружения на сервере.** Никаких ключей в коде,
   в `NEXT_PUBLIC_*` переменных и в браузере. `.env` не коммитится; есть `.env.example`.
5. **Не выдавать за официальный сервис.** На каждой странице виден бейдж «Концепт для конкурса».
   Официальный логотип вуза не использовать.
6. **Только лицензионно чистые материалы.** Новый шрифт, иконку, библиотеку — записать
   в таблицу лицензий в `README.md`.

## Интерфейс

- **Mobile-first.** Всё работает на ширине **360 px**. Проверяй сначала телефон, потом десктоп.
- Каждый экран со списком или данными имеет **три состояния**: загрузка (скелетон),
  пусто (понятный текст + действие), ошибка (что случилось + кнопка «Повторить»).
- Области нажатия — не меньше 44×44 px. У иконок без подписи — `aria-label`.
- Используй токены и компоненты из `docs/DESIGN.md`, а не случайные цвета.
- **Компьютер (≥ 1024 px)** — боковое меню и сетки в 2–3 колонки. Любую сетку начинай с `grid-cols-1`
  (иначе длинный текст раздвигает колонку и на 360 px появляется горизонтальная прокрутка).
- Демо-режим (`DEMO_MODE=1`): действия, которые могут «сломать» общий демо-аккаунт, отключаются
  на сервере (`lib/config.ts`), а в интерфейсе объясняется почему.

## Как работать

1. Прочитай нужные документы из `docs/`.
2. Если задача больше пары файлов — сначала коротко опиши план.
3. Сделай задачу маленькими шагами; после каждого шага код должен запускаться.
4. Проверь результат: сборка, линтер, тесты, вид на 360 px.
5. Для изменений во входе, доступе к данным или API — запусти субагента `security-reviewer`.
   Для изменений интерфейса — `ui-reviewer`.
6. Добавь запись в `docs/AI_LOG.md` (шаблон внутри файла) и отметь прогресс в `docs/ROADMAP.md`.

Новые запросы к данным — **только** в `lib/data/*`, функция принимает `StudentContext`,
`StaffContext`, `TeacherContext` или `UserContext` (любой вошедший, `requireUser()`) из `lib/auth/guards.ts`, а не голый id.
Роли: `STUDENT`, `STAFF`, `TEACHER` (преподаватель из `schedule.csv`, аккаунт создаёт импорт; оценки ставит только
по своим назначениям `TeachingAssignment` — семинары и практические занятия группы).
Не хардкодь названия факультетов, групп и дисциплин — бери их из базы.

## Команды

| Команда | Что делает |
|---|---|
| `docker compose up -d db` | Поднять PostgreSQL локально |
| `npm run db:setup` | Миграции + импорт данных вуза + демо-наполнение |
| `npm run data:import` | Проверить и загрузить `data/university/*` (`-- --check` — только проверить, `-- --dir <путь>` — другая папка). Пишет `credentials.csv` — НЕ коммитить |
| `npm run dev` | Режим разработки, http://localhost:3000 |
| `npm run db:migrate -- --name <имя>` | Новая миграция после правки `schema.prisma` |
| `npm run db:reset` | Пересоздать базу с нуля: миграции + импорт + демо-контент |
| `npm run db:seed` | Пересоздать демо-контент (заявки, оценки, объявления, уведомления, дедлайны) поверх импорта |
| `npm run lint` · `npm run typecheck` · `npm test` | Проверки — запускать перед каждым коммитом |
| `npm run build` | Продакшен-сборка |

## Проверка в браузере

Для проверки интерфейса используй Playwright (уже установлен в облачном окружении):
ширина 360 px, вход под тестовым аккаунтом, скриншоты — в `docs/screenshots/` по правилам из README папки.
Перед запуском продакшен-сервера убедись, что старый процесс на порту 3000 остановлен,
иначе браузер получит файлы от предыдущей сборки.

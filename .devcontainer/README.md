# Кабинет в GitHub Codespaces

Это виртуальная машина в браузере — ничего не нужно устанавливать.

1. Первое создание занимает **3–5 минут**: ставятся зависимости, создаётся база с демо-данными, собирается кабинет.
   Ход работы виден в терминале внизу.
2. Когда всё готово, кабинет **откроется в новой вкладке** браузера.
   Если не открылся: внизу вкладка **PORTS** → строка **3000** → значок 🌐 (*Open in Browser*).

## Повторные открытия и обновления

Создавать Codespace заново **не нужно**. Открывайте тот же: github.com/codespaces → нужный Codespace.

- При каждом открытии он **сам скачивает свежую версию** из GitHub и пересобирает кабинет,
  только если код изменился (около минуты). Без изменений — кабинет готов за несколько секунд.
- Если Codespace уже открыт, а вы хотите подтянуть новую версию: в терминале «кабинет» нажмите
  `Ctrl+C` и выполните `bash .devcontainer/start.sh`.
- Если вы сами что-то меняли в файлах, автообновление пропускается, чтобы не потерять ваши правки.
- Ваши заявки и изменения в базе сохраняются между открытиями. Демо-данные сбрасываются к исходным,
  только когда в обновлении изменились сами демо-данные. Сбросить вручную: `npm run db:seed`.

## Если при входе «This page couldn't load»

Значит, сервер запущен без настройки для адреса Codespaces (было в первых версиях конфигурации).
В терминале «кабинет» нажмите `Ctrl+C` (пока сервер работает, набранные команды не выполняются),
затем выполните по очереди:

```bash
git pull
bash .devcontainer/start.sh
```

## Квота

- Время тратится, **только пока Codespace запущен**. Остановленный не расходует часы,
  только место на диске (его в бесплатной квоте с запасом).
- **Останавливайте после работы:** github.com/codespaces → «…» → *Stop codespace*.
  Через 30 минут бездействия он остановится сам.
- Остановленный Codespace, который долго не открывали (по умолчанию 30 дней), GitHub удаляет —
  тогда просто создайте новый.

> Ссылка на Codespace доступна только вам: по умолчанию порт приватный. Для жюри будет отдельный сервер.

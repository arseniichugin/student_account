# Данные вуза — заменяемые файлы

В этой папке лежат три файла, из которых кабинет берёт **всю структуру вуза**: факультеты, группы,
студентов, преподавателей, аудитории и расписание. Сейчас здесь вымышленный «Хогвартс»
(собран генератором `tools/schedule-generator/` и `tools/campus-map/`). Все данные вымышлены.

Файлы можно заменить своими с той же структурой — другой вуз, другие факультеты, группы и студенты.
Кабинет не завязан на конкретные названия: после импорта всё работает на новых данных.

| Файл | Что внутри | Обязателен |
|---|---|---|
| `students.csv` | студенты: ФИО, почта, зачётка, факультет, курс, группы | да |
| `schedule.csv` | расписание: одна строка на пару «занятие × группа» | да |
| `campus-map.json` | корпуса и аудитории для карты кампуса | нет (без него — предупреждение) |

## Как заменить данные

```bash
# 1. Положите свои файлы в data/university/ (или в любую папку)
# 2. Проверьте их, ничего не меняя в базе:
npm run data:import -- --check
# 3. Загрузите:
npm run data:import                       # из data/university
npm run data:import -- --dir путь/к/папке # из другой папки (или UNIVERSITY_DATA_DIR=путь)
# 4. Обновите демо-контент (заявки, оценки, объявления) под новые группы и дисциплины:
npm run db:seed
```

С нуля всё сразу: `npm run db:setup` (миграции + импорт + демо-наполнение).

## Как заменить вуз

1. Замените три файла (форматы ниже) и проверьте их: `npm run data:import -- --check`.
2. Задайте **название вуза** в переменной окружения `UNIVERSITY_NAME` (`.env` или окружение
   сервера / `docker-compose.yml`), например `UNIVERSITY_NAME="Тестовый университет"`. Оно видно
   в заголовке вкладки, логотипе и профиле. Не задано — «Хогвартс». Пересобирать приложение не нужно,
   достаточно перезапустить.
3. Загрузите данные и демо-контент: `npm run data:import && npm run db:seed`.

Названия факультетов, групп, дисциплин и аудиторий кабинет берёт только из базы — в коде их нет.

**Демо-контент рассчитан на осень 2026 года.** `prisma/seed.ts` создаёт заявки, оценки, объявления
и дедлайны с датами октября–ноября 2026 (осенний семестр 2026/27). Для расписания другого периода
само расписание покажется верно, но демо-заявки и дедлайны окажутся «в прошлом» или «в будущем» —
поправьте даты в `prisma/seed.ts`.

## Общие правила для CSV

- Кодировка UTF-8, **с BOM или без** (Excel сохраняет с BOM — это нормально).
- Разделитель — `;`. Файл с `,` тоже поймём: разделитель определяется по строке заголовков.
- Первая строка — заголовки. Порядок колонок любой, лишние колонки не мешают.
- Значение с `;`, кавычками или переводом строки берите в двойные кавычки: `"Онлайн; ссылка ниже"`, `"он сказал ""да"""`.
- Пустые строки (в том числе в конце файла) пропускаются.

## `students.csv`

Пример строки:

```
ID студента;Фамилия;Имя;Отчество;Email;Номер зачётки;Факультет;Код факультета;Курс;Направление;Академическая группа;Языковая группа 1;Языковая группа 2
260001;Шарова;Лариса;Вячеславовна;larisa.sharova26@hogwarts.example.org;26ГР0001;Факультет Гриффиндор;ГР;1;Магические науки и практики, профиль «Гриффиндор»;1-ГР-1;1-ГР-1 (1);1-ГР-1 (5)
```

| Колонка | Обязательна | Пример | Смысл и проверки |
|---|---|---|---|
| `ID студента` | да | `260001` | Постоянный идентификатор. По нему повторный импорт узнаёт студента: его заявки, оценки и пароль сохраняются. Уникален |
| `Фамилия` | да | `Шарова` | ФИО: буквы любого алфавита, пробел, дефис, апостроф, точка; до 100 символов |
| `Имя` | да | `Лариса` | |
| `Отчество` | нет | `Вячеславовна` | Можно оставить пустым или убрать колонку |
| `Email` | да | `larisa.sharova26@…` | Уникален. **Логин = часть до `@`** (латиница, цифры, `.`, `-`, `_`), тоже уникален. Логины `dekanat.*` заняты деканатами |
| `Номер зачётки` | да | `26ГР0001` | Уникален |
| `Факультет` | да | `Факультет Гриффиндор` | Полное название. У одного кода — одно название |
| `Код факультета` | да | `ГР` | Короткий код. Из него логин деканата: `dekanat.` + код латиницей (`ГР` → `dekanat.gr`). Порядок первого появления в файле — «факультет №1, №2…» |
| `Курс` | да | `1` | Целое число 1–10. У всех студентов одной академической группы курс и факультет совпадают |
| `Направление` | да | `Магические науки…` | Направление подготовки |
| `Академическая группа` | да | `1-ГР-1` | Название — **точно как в колонке `group` расписания** |
| `Языковая группа 1`, `Языковая группа 2` | нет | `1-ГР-1 (5)` | Подгруппы (языки и т. п.). Тоже должны быть в расписании. Можно оставить пустыми |

Группа не может быть одновременно академической у одного студента и языковой у другого.

## `schedule.csv`

Формат РУЗ (`tools/schedule-generator/spec/mgimo_ruz.py`): **одна строка на пару «занятие × группа»**.
Лекция потока для трёх групп — три строки с одинаковым `lessonOid`; в базе это одно занятие, связанное с тремя группами.

| Колонка | Обязательна | Пример | Смысл и проверки |
|---|---|---|---|
| `lessonOid` | да | `102109` | Идентификатор занятия. Все строки одного занятия должны совпадать во всём, кроме группы |
| `date` | да | `2026.09.01` | Дата, `ГГГГ.ММ.ДД` (можно `ГГГГ-ММ-ДД`), по Москве |
| `beginLesson`, `endLesson` | да | `09:00`, `10:20` | Время `ЧЧ:ММ`, конец позже начала |
| `lessonNumberStart`, `lessonNumberEnd` | нет | `1` | Номер пары |
| `discipline` | да | `Трансфигурация` | Дисциплина |
| `disciplineOid` | нет | `501` | |
| `kindOfWork` | да | `Лекция` | Вид работы: лекция, семинар, экзамен… **Оценки ставит** тот, кто ведёт у группы `Семинар` или `Практическое занятие` (не `replaced`); итоговый контроль — занятие `Экзамен` или `Зачёт` этой группы по дисциплине |
| `lecturer` | колонка да, значение нет | `Арсеньева П.Н.` | Краткое ФИО преподавателя; пусто — без преподавателя |
| `lecturer_title` | нет | `ст. преподаватель Арсеньева Полина Николаевна` | Звание + полное ФИО (звание отрезается) |
| `lecturerOid` | нет | `2058` | Идентификатор преподавателя; если пуст — используется краткое ФИО |
| `lecturerEmail`, `lecturer_rank` | нет | `p.arseneva@…`, `доцент` | Из почты — **логин преподавателя** (часть до `@`, как у студентов). Он не должен совпадать с логином студента и не может начинаться с `dekanat.` — иначе ошибка. Нет почты — нет аккаунта. `lecturer_rank` — должность в кабинете |
| `group` | да | `1-ГР-1 (1)` | Группа. Группы, которых нет у студентов, тоже сохраняются (видны в поиске расписания) |
| `groupOid` | нет | `1002` | |
| `stream` | нет | `1-ГР, поток 1` | Поток (для лекций) |
| `subGroup` | нет | | |
| `auditorium` | колонка да, значение нет | `4144`, `Манеж-1` | Номер аудитории, как на карте. **Пусто — онлайн или без аудитории** |
| `building` | колонка да, значение нет | `Главный корпус` | Название корпуса, как `name` на карте |
| `note` | нет | `Отмена: болезнь преподавателя` | Причина изменения |
| `url1` | нет | `https://hogwarts.example.org/meet/100983` | Ссылка на онлайн-занятие. Только `http://` или `https://` |
| `url1_description` | нет | `Ссылка на конференцию` | |
| `status` | нет | `normal` | `normal` / `moved` / `cancelled` / `replaced` (замена преподавателя). Нет колонки или пусто — `normal` |

Остальные колонки РУЗ (`lesson_key`, `dayOfWeek`, `auditoriumOid`, `url2`…) допускаются и пропускаются.
Значения — не длиннее 300 символов, ссылка `url1` — не длиннее 2048.

## `campus-map.json`

```json
{
  "source": "откуда данные",
  "buildings": [
    { "id": "main", "name": "Главный корпус", "abbr": "ГК", "address": "Замковая ул., 1",
      "floors": [1, 2, 3, 4], "wings": [0, 1], "maxRoom": 79, "scheme": "ЭКNN: этаж · крыло · номер" }
  ],
  "rooms": [
    { "id": 1, "number": "2031", "building": "main", "type": "Административное помещение",
      "capacity": 10, "floor": 2, "wing": 0, "purpose": "Ректорат", "bookable": false }
  ]
}
```

Файл проверяет **одна схема** (`lib/campus-map/schema.ts`) — и при импорте, и на странице карты:
что принял `npm run data:import -- --check`, то покажет и `/map`.

| Поле | Обязательно | Смысл и проверки |
|---|---|---|
| `buildings` | да | Список корпусов: от 1 до 50 |
| `buildings[].id` | да | Уникальный ключ корпуса — строка до 64 символов |
| `buildings[].name` | да | Уникальное название — **как в колонке `building` расписания** |
| `buildings[].abbr` | да | Короткое обозначение на карте (до 16 символов): `ГК` |
| `buildings[].address` | да | Адрес — показывается в карточке аудитории |
| `buildings[].floors` | да | Этажи — непустой список целых чисел от −5 до 100: `[1, 2, 3, 4]` |
| `buildings[].wings` | нет | Крылья: `[0, 1]`; нет крыльев — `[null]` (так и по умолчанию) |
| `buildings[].maxRoom`, `scheme` | нет | Подсказка о нумерации помещений |
| `rooms` | да | Список аудиторий (может быть пустым), до 10 000 |
| `rooms[].number` | да | Номер — **как в колонке `auditorium` расписания**. Уникален без учёта регистра, «ё» и лишних пробелов |
| `rooms[].building` | да | `id` корпуса из `buildings` |
| `rooms[].type` | да | Тип помещения: «Лекционная», «Административное помещение»… |
| `rooms[].floor` | да | Этаж — одно из значений `floors` его корпуса |
| `rooms[].capacity`, `wing`, `purpose`, `bookable` | нет | Вместимость, крыло, назначение служебного помещения, можно ли ставить занятия (по умолчанию `true`) |

Строки — не длиннее 300 символов, файл — не больше 5 МБ. Ошибки печатаются с местом и номером:
`campus-map.json, rooms[3] (номер «101»): поле «type» — обязательное поле не заполнено`.

Аудитории и корпуса из расписания, которых нет на карте, — **предупреждение**, а не ошибка: занятия загрузятся.
Другие поля в файле допускаются: импорт их пропускает, а в браузер для карты они не передаются.

## Что делает импорт (`npm run data:import`)

1. **Проверяет все три файла до любых изменений в базе.** Обязательные колонки, форматы дат и времени,
   курс, длина значений, уникальность ID/почты/зачётки/логина, что группы студентов есть в расписании, что строки одного
   занятия не противоречат друг другу, корректность карты. При ошибках печатает до 30 сообщений и выходит
   с кодом ≠ 0. Файл больше 50 МБ (`campus-map.json` — больше 5 МБ) не читается вовсе — сразу ошибка «файл слишком большой»:

   ```
   Ошибки в файлах:
     ✖ students.csv, строка 15: колонка «Академическая группа» — группы «1-ГР-9» нет в schedule.csv
     ✖ schedule.csv, строка 4: колонка «date» — «2026.13.09» не дата в формате ГГГГ.ММ.ДД (например, 2026.09.01)

   Найдено 2 ошибки, база не изменена.
   ```

2. **Загружает всё одной транзакцией** — либо всё, либо ничего. Основной набор (~23,5 тыс. строк расписания,
   990 студентов) грузится примерно за 10–15 секунд.
3. **Повторный импорт безопасен.** Студенты сопоставляются по `ID студента`: их заявки, оценки и пароли
   сохраняются. Студенты, которых нет в новом файле, удаляются вместе с аккаунтами. Расписание заменяется целиком.
   Группы, дисциплины, преподаватели и аудитории обновляются по названию/номеру/ключу — ссылки на них не ломаются.
   Если у того же `ID студента` сменились логин или ФИО, импорт закрывает сессии аккаунта и пишет предупреждение
   «Проверьте…»: возможно, ID отдали другому человеку — тогда выдайте ему новый пароль.
4. **Аккаунты.**
   - Каждому новому студенту — аккаунт с логином = часть почты до `@` и **случайным паролем**
     (12 символов, без похожих `0/O`, `1/l/I`). В базе только хеш argon2id. Пароли существующих аккаунтов не меняются.
   - Деканат: по одному сотруднику на факультет, логин `dekanat.<код латиницей>` (`ГР` → `dekanat.gr`).
   - **Преподаватели** с почтой в `lecturerEmail`: логин = часть почты до `@`, случайный пароль (строка с ролью
     «Преподаватель» в `credentials.csv`). Повторный импорт узнаёт преподавателя по `lecturerOid` и сохраняет
     аккаунт, пароль и выставленные им оценки; сменилась почта — меняется логин, пароль прежний.
     Преподаватель, исчезнувший из расписания, теряет аккаунт (его оценки остаются у студентов).
   - **Назначения «преподаватель × дисциплина × группа»** (кто ставит оценки) пересчитываются из расписания при
     каждом импорте; адреса журналов сохранившихся назначений не меняются.
   - **Тестовые аккаунты для жюри:** 3 студента (факультеты №1–3, курсы 1–3, наименьший ID; переопределяется
     `TEST_STUDENT_LOGINS=логин1,логин2,…`) и все деканаты получают пароль из `DEMO_PASSWORD`
     (по умолчанию `Hogwarts2026`) — **при каждом импорте**. Сменить пароль тестового аккаунта в кабинете нельзя
     (флаг в базе, независимо от `DEMO_MODE`).
   - **2 тестовых преподавателя:** семинаристы групп первого и второго тестового студента (разные люди; из кандидатов —
     с наибольшим числом групп); переопределяется `TEST_TEACHER_LOGINS=логин1,логин2`. Пароль — тоже `DEMO_PASSWORD`,
     импорт печатает их логины и группы. Бывший тестовый преподаватель получает новый случайный пароль.
   - Студент, который **перестал быть тестовым** (убран из `TEST_STUDENT_LOGINS`), получает новый случайный пароль:
     демо-пароль знают все посетители стенда. Его сессии закрываются, новый пароль — в `credentials.csv`.

## `credentials.csv` — логины и пароли

Импорт записывает логины и пароли в **`credentials.csv` в корне репозитория** (другой путь —
`--credentials путь` или `CREDENTIALS_FILE`): `Логин;ФИО;Email;Роль;Пароль`, `;`, UTF-8 с BOM — открывается в Excel.

- В файле: аккаунты, созданные этим или прошлыми импортами, плюс тестовые аккаунты с демо-паролем.
  Повторный импорт **дополняет** файл, а не затирает: пароли, выданные раньше, не теряются.
  Аккаунты удалённых студентов из файла убираются.
- **Файл нельзя коммитить и публиковать** — в нём пароли в открытом виде. Он уже в `.gitignore` и `.dockerignore`.
  Раздайте пароли студентам и удалите файл (или храните в защищённом месте).
- В консоль пароли не печатаются — только путь к файлу.
- Значения, которые таблица приняла бы за формулу (`=`, `+`, `-`, `@` в начале), записываются с апострофом.
- Файл пишется через `credentials.csv.tmp`. Если прошлый импорт оборвался после загрузки в базу, но до
  переименования, следующий импорт объединит `.tmp` с основным файлом (только пароли, которые подходят к базе)
  и сообщит об этом.
- В Docker (`docker compose run --rm migrate`) файл появляется в `secrets/credentials.csv` на сервере
  (создайте папку заранее: `mkdir -m 700 secrets`); остальной проект контейнеру на запись не открыт.

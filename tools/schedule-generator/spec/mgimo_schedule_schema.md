# Схема данных для синтетического расписания МГИМО

Спецификация для генерации правдоподобных данных расписания: их можно подставить в макет личного кабинета. Структура повторяет модель системы РУЗ (ruz.mgimo.ru) и совместима с форматом скрипта `mgimo_ruz.py`. Если позже удастся выгрузить настоящие данные, они встанут в макет без переделки.

**Пометки об источниках:**
- **[сайт]** — взято со страницы mgimo.ru/study/schedule (осенний семестр 2026/27);
- **[РУЗ]** — поле или сущность из API системы РУЗ (по открытому описанию такой же системы у ВШЭ). У МГИМО названия полей могут немного отличаться;
- **[допущение]** — разумное значение по умолчанию. Это параметр генерации, его можно менять;
- **[сверить]** — правдоподобное значение, которое стоит проверить на mgimo.ru.

## 1. Общие соглашения

| Характеристика | Значение |
|---|---|
| Кодировка | UTF-8. CSV-файлы — UTF-8 с BOM (`utf-8-sig`), чтобы Excel правильно показывал кириллицу |
| Разделитель CSV | `;`, первая строка — заголовки |
| Язык значений | русский |
| Внутренний ID | `*_oid`: целое число > 0, уникальное в пределах таблицы [РУЗ] |
| Внешний ID | `*_gid`: UUID v4, ссылка на запись в учётной системе вуза; необязателен [РУЗ] |
| Дата в БД | ISO, `YYYY-MM-DD` |
| Дата в JSON API и в CSV формата `mgimo_ruz.py` | `YYYY.MM.DD` [РУЗ] |
| Время | `HH:MM`, 24-часовой формат, часовой пояс Europe/Moscow (UTC+3) |
| День недели | `dayOfWeek`: 1 = понедельник … 7 = воскресенье; `dayOfWeekString`: «Пн», «Вт», «Ср», «Чт», «Пт», «Сб», «Вс» [РУЗ] |
| Пустые значения | `NULL` в БД, пустая строка в CSV, `null` в JSON |
| Персональные данные | только вымышленные: ФИО сгенерированы, e-mail на домене `example.org`, никаких реальных преподавателей и студентов |

## 5. Связи

- факультет 1 — N кафедр, программ, групп, потоков;
- кафедра 1 — N преподавателей и дисциплин;
- корпус 1 — N аудиторий;
- поток N — M академических групп (через `stream_groups`);
- студент N — 1 академическая группа; студент N — M языковых групп (через `student_groups`);
- занятие N — 1 дисциплина, вид занятия, преподаватель, аудитория;
- занятие 1 — N записей аудитории (`lesson_audience`);
- шаблон 1 — N занятий.

## 6. Правила генерации

### 6.1 Жёсткие (нарушать нельзя)

1. `end_time − begin_time = 80 мин`, а время совпадает с сеткой факультета.
2. Номер пары от 1 до 8; обеденный слот свободен.
3. Нет занятий в воскресенье, 2026-11-04 и вне дат семестра или сессии.
4. Преподаватель в одном слоте ведёт только одно занятие.
5. В аудитории в одном слоте только одно занятие, и её вместимость не меньше суммарного размера аудитории занятия.
6. У студента нет двух занятий в одном слоте. Это проверяется через `student_groups` и `stream_groups`. Языковые группы одной академической группы могут заниматься параллельно, но только в разных аудиториях.
7. Лекции ведутся у потока или группы, семинары и практические — у группы, языки — у языковой группы.
8. Языковые дисциплины ведут преподаватели языковых кафедр; кафедра преподавателя совпадает с кафедрой дисциплины.
9. Экзамены только в сессию; у группы не больше одного экзамена в день, между экзаменами минимум 2 дня; консультация за 1–2 дня до экзамена.
10. `day_of_week`, `week_number` и `week_parity` согласованы с `date`.

### 6.2 Для правдоподобия [допущение]

- 3–4 пары в день у группы, максимум 5; не больше одного «окна».
- Очная форма — в основном пары 1–5; пары 6–8 — магистратура, очно-заочная форма и факультативы.
- Иностранные языки — заметная часть нагрузки: 3–6 пар в неделю на первый язык, 2–3 на второй.
- Часть дисциплин чередуется по неделям Н/Ч.
- Нагрузка преподавателя — до 18 пар в неделю.
- 2–5% занятий с изменениями (`moved`, `cancelled`, `replaced`) и заполненным `note`: расписание «в режиме ежедневной онлайн-корректировки» [сайт].
- 0–5% онлайн-занятий с `url1`.

## 8. Форматы выдачи

### 8.1 SQL (SQLite или PostgreSQL)

Нормализованные таблицы из раздела 4: ключи `*_oid`, внешние ключи, `CHECK` на перечисления, индексы на `lessons(date)`, `lessons(lecturer_oid)`, `lessons(auditorium_oid)`, `lesson_audience(audience_type, audience_oid)`. Удобно выгружать одним файлом `schema.sql` (DDL) плюс `data.sql` (INSERT) или сразу готовым `mgimo_schedule.sqlite`.

### 8.2 Плоский CSV, совместимый с `mgimo_ruz.py`

Файл `mgimo_schedule.csv`: одна строка на пару «занятие × группа» (лекция потока из 4 групп даёт 4 строки), разделитель `;`, кодировка UTF-8 с BOM, дата в формате `YYYY.MM.DD`. Колонки строго в этом порядке:

```
lesson_key;lessonOid;date;dayOfWeek;dayOfWeekString;beginLesson;endLesson;lessonNumberStart;lessonNumberEnd;discipline;disciplineOid;kindOfWork;kindOfWorkOid;lecturer;lecturer_title;lecturerOid;lecturerEmail;lecturer_rank;group;groupOid;stream;streamOid;subGroup;subGroupOid;auditorium;auditoriumOid;building;buildingOid;note;url1;url1_description;url2;url2_description
```

`lesson_key` = `lessonOid|groupOid|subGroupOid` (пустое значение, если подгруппы нет).

Второй файл, `mgimo_schedule_entities.csv`, со справочником для поиска: `kind;id;label;description`, где `kind` ∈ `group`, `person`, `auditorium`.

## 9. Именование [допущение]

Настоящий формат названий групп МГИМО неизвестен, поэтому ниже шаблоны, которые стоит один раз выбрать и держать во всех данных.

| Объект | Шаблон | Пример |
|---|---|---|
| Академическая группа | `{факультет}-{курс}-{NN}` | МО-1-01 |
| Языковая группа | `{ЯЗЫК}-{факультет}{курс}-{NN}` | АНГЛ-МО1-03, АРАБ-МО1-02 |
| Поток | `{факультет}-{курс}, поток {N}` | МО-1, поток 1 |
| Аудитория | `{корпус}{этаж}{NN}` | 1047 |
| Преподаватель (кратко) | `Фамилия И.О.` | Иванова А.С. |

Языки для генерации (МГИМО преподаёт очень много языков): английский, французский, немецкий, испанский, итальянский, арабский, китайский, японский, турецкий, персидский, корейский, хинди, португальский и другие. Первый язык почти у всех английский или язык специализации.

## 10. Проверка сгенерированных данных (SQL)

```sql
-- 1. Преподаватель в двух местах одновременно
SELECT lecturer_oid, date, lesson_number_start, COUNT(*)
FROM lessons WHERE status <> 'cancelled'
GROUP BY lecturer_oid, date, lesson_number_start HAVING COUNT(*) > 1;

-- 2. Занятая дважды аудитория
SELECT auditorium_oid, date, lesson_number_start, COUNT(*)
FROM lessons WHERE auditorium_oid IS NOT NULL AND status <> 'cancelled'
GROUP BY auditorium_oid, date, lesson_number_start HAVING COUNT(*) > 1;

-- 3. Занятия в воскресенье, праздник или вне семестра
SELECT * FROM lessons
WHERE day_of_week = 7 OR date = '2026-11-04'
   OR date NOT BETWEEN '2026-09-01' AND '2027-01-31';

-- 4. Чётность недели не совпадает с датой
SELECT * FROM lessons
WHERE week_number <> CAST((julianday(date) - julianday('2026-08-31')) / 7 AS INT) + 1;
```

Плюс проверка пересечений у студента: сгруппировать занятия по `student_oid × date × lesson_number_start` через `student_groups`, `stream_groups` и `lesson_audience` — пересечений быть не должно.
